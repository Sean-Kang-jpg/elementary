# 프로젝트 전체 구조

Status: **Current**
Last updated: 2026-09-29
Owner: Product

개발자가 아닌 사람이 처음부터 읽어도 구조가 잡히도록 쓴 문서다. 세부 사항은
각 절이 가리키는 문서를 따르고, 충돌하면 그쪽이 우선한다.

숫자는 모두 **2026-09-29 시점 기록**이다. 데이터가 갱신될 때마다 바뀌므로 판단
전에 다시 확인한다. 용량은 `python etl/check_capacity.py`로 그 자리에서 다시 잴 수 있다.

---

## 1. 한 장으로 보는 전체

```
[공공 데이터 원천]        나라가 공개하는 파일·API
      │
      ▼
[ETL]  Python 스크립트   내려받기 → 정리 → 맞춰 붙이기 → 검사
      │
      ▼
[Supabase 데이터베이스]   비공개 원본 계층 + 공개 조회 계층
      │
      ▼
[웹 앱]  React + 네이버지도   브라우저가 공개 계층만 읽는다
      │
      ▼
[Vercel]  release 브랜치에 push하면 배포
```

**ETL**과 **웹 앱**은 서로 독립적으로 움직인다. 데이터를 갱신해도 앱을 다시
배포할 필요가 없고, 앱을 배포해도 데이터는 그대로다.

---

## 2. 이 제품이 하는 일

아파트가 **어느 초등학교에 배정되는지**를 공식 근거로 알려준다. 그리고 그
학교에 배정된 다른 아파트들, 학년별 학생·학급 수, 주거 조건을 함께 보여준다.

**가까운 학교가 아니라 배정되는 학교**를 다룬다는 점이 이 제품의 존재 이유다.
경쟁 서비스는 도보 거리를 보여주는데, 거리와 배정은 다르다.

제품이 어디로 가려 하는지는 [`product/PRODUCT_CONCEPT.md`](product/PRODUCT_CONCEPT.md).

## 3. 데이터는 어디서 와서 어떻게 화면에 닿는가

### 3.1 원천 — 네 가지

| 원천 | 무엇을 주나 | 갱신 |
| --- | --- | --- |
| **학구도** (통학구역 폴리곤) | **배정의 근거.** 지도 위에 그려진 통학구역 경계 | 연 단위 |
| **학교알리미** (schoolinfo) | 학교 기본정보, 학년별 학생·학급 수 | 정기 수집 |
| **K-apt** (공동주택관리정보) | 아파트 세대수·동수·연식·주차·임대 구성 | 정기 수집 |
| **아파트 기준자료** | 아파트의 좌표와 식별자 | **2024-10자 고정** |

마지막 항목은 주의가 필요하다. `archive/GAS/GAS/임시/apt_mst_info_202410.csv`
라는 **고정된 파일**이고, 아파트 식별자 절반 이상이 여기서 나온다. 갱신되지
않는 상태로 붙들려 있다.

### 3.2 배정은 어떻게 정해지나

이 제품에서 가장 중요한 계산이다.

```
아파트 좌표  ──┐
               ├─→ 공간 조인(polygon spatial join) ─→ 어느 통학구역 안인가
통학구역 폴리곤 ┘                                          │
                                                          ▼
                                            그 구역의 학교 = 배정 학교
```

**"아파트가 어느 통학구역 폴리곤 안에 있는가"를 지도 계산으로 판정한다.**
이름이 비슷하다고 짝지우는 방식이 아니다. 근거는
[`decisions/ADR-002-official-school-zone-source.md`](decisions/ADR-002-official-school-zone-source.md).

여기서 실무적 난점이 하나 있다. 통학구역 자료는 학교 이름이 아니라 **학구도
이름**(`서울교동초통학구역`)으로 기록돼 있어서, 그 이름을 실제 학교에 연결하는
작업이 필요하다. 지역마다 표기 방식이 달라서(도시명을 붙이는 지역, 떼는 지역,
`공동통학구역`·`광역통학구역` 같은 형식) 지역을 추가할 때마다 이 부분이 가장
손이 많이 간다.

### 3.3 ETL — 여섯 단계

ETL은 "Extract(추출) · Transform(변환) · Load(적재)"의 약자다. 원천 데이터를
가져와 쓸 수 있는 형태로 바꿔 데이터베이스에 넣는 과정 전체를 말한다.

| # | 단계 | 하는 일 |
| --- | --- | --- |
| 1 | 보관 | 원천 파일을 비공개 저장소에 그대로 저장하고 체크섬 기록 |
| 2 | 검사 | 임시 테이블에 넣고 형식·누락을 검사 |
| 3 | 적재 | 학교·아파트·배정 마스터 테이블에 반영 |
| 4 | 갱신 | 공개용 조회 테이블을 통째로 다시 만든다 (원자적) |
| 5 | 감사 | 자동 검사 52항목 + 원격 건수·권한 확인 |
| 6 | 확인 | 웹 앱 smoke 테스트 통과 후에만 기록을 "완료"로 남긴다 |

**1단계에서 원본을 그대로 보관하는 이유**는 나중에 "그때 그 숫자가 왜 그랬나"를
재현할 수 있어야 하기 때문이다. 45일간 보관한다.

**4단계가 원자적(atomic)이라는 것**은 절반만 갱신된 상태가 사용자에게 보이지
않는다는 뜻이다. 실패하면 이전 데이터가 그대로 유지된다.

전체 체크리스트는 [`operations/OPERATION_PLAN.md`](operations/OPERATION_PLAN.md)의
Refresh Runbook.

### 3.4 데이터베이스 — 2층 구조

Supabase(PostgreSQL 기반 서비스)를 쓴다. **핵심은 브라우저가 볼 수 있는 것과
볼 수 없는 것을 분리한 것이다.**

```
┌─ 공개 계층 (브라우저가 읽는다) ─────────────┐
│  school_master                학교 정보     │
│  school_apartment_serving     배정 관계     │
│  apartment_academy_summary    학원 개수     │
│  + 함수 3개 (필터, 학원 근접)                │
└─────────────────────────────────────────────┘
┌─ 비공개 계층 (service_role·관리자만) ───────┐
│  정규화 마스터 · 배정 링크 · 이력            │
│  ETL 실행 기록 · 임시 데이터 · 원본 스냅샷    │
└─────────────────────────────────────────────┘
```

**RLS**(Row Level Security, 행 수준 보안)가 이 경계를 강제한다. 프론트엔드
코드에 비공개 테이블 조회를 써넣어도 운영에서는 거부된다.

공개 계층을 셋으로 좁혀두는 이유는, 화면에 필요한 모양으로 미리 만들어 두면
브라우저가 여러 테이블을 조합할 필요가 없어 빠르고, 노출 면적도 작기 때문이다.

정확한 계약은 [`architecture/DATA_CONTRACTS.md`](architecture/DATA_CONTRACTS.md).

### 3.5 웹 앱

React 18 + TypeScript + Vite + Tailwind + 네이버 지도.

- 상태는 `src/contexts/AppContext.tsx` 한 곳에 모여 있다 (필터, 지도 위치, 선택)
- Supabase 조회는 `src/services/dataService.ts` 한 곳을 통한다
- 지도 마커는 React 밖에서 직접 관리한다 (수천 개를 다루려면 그게 빠르다)
- 화면을 아래에서 끌어올리는 **바텀시트**가 상세 화면의 기본 형태다

지도 축척에 따라 **조회 단위가 바뀐다.** 넓게 보면 시·도 집계, 좁히면 개별
학교를 읽는다. 전국 6,302개 학교를 한 번에 읽지 않기 위한 장치다.

## 4. 지역은 어떻게 늘려 왔는가

전국을 한 번에 바꾸지 않고 **웨이브**로 나눠 넣었다. 지역마다 통학구역 표기가
달라서, 한 지역을 넣을 때마다 검증하고 넘어간다.

```
수도권(서울·경기·인천) → 대전 → 울산 → 제주 → 대구 → 광주·부산·세종·충북·충남 → 전남·강원·전북·경북·경남
```

**어느 지역이 공개 상태인지는 `etl/region_registry.json` 한 파일이 정한다.**
코드와 SQL과 프론트엔드가 모두 이 파일을 읽는다. 지역을 늘리는 것은 이 파일의
`status`를 바꾸는 일이고, 코드를 고치는 일이 아니다.

2026-09-29 기준 **17개 시도 전체가 공개 상태**이고, 확장은 끝났다.

| 항목 | 값 |
| --- | --- |
| 공개 지역 | 17 / 17 |
| 학교 | 6,302개 |
| 아파트 단지 | 45,853개 |
| 배정 관계 | 48,189행 |
| 데이터베이스 용량 | 214.8 MB / 500 MB (43.0%) |

지역별 합계가 테이블 전체 합계와 정확히 일치한다. 즉 **범위 밖 행이 하나도 없다.**

정책 근거는 [`decisions/ADR-003-nationwide-rollout.md`](decisions/ADR-003-nationwide-rollout.md).

### 4.1 전국을 다 넣고 나서 남은 빈틈

전국 적재는 끝났지만 데이터가 완벽하지는 않다. **여기에 적는 33개 단지는
지도에 아예 나오지 않는다.** 잘못된 학교로 배정되는 것이 아니라 조용히 빠진다.
배정이 없으면 공개 조회 테이블에 행이 생기지 않고, 아파트는 그 테이블을 통해서만
화면에 닿기 때문이다.

**(1) 나라 데이터에 학교가 없어서 — 4개교, 13단지**

실제로 운영 중이고 학교알리미에는 있는데, 학교 식별번호를 주는 **학교기본정보에만
빠져 있는** 학교가 넷 있다. 식별번호가 없으면 학교 테이블에 넣을 수 없고, 그
학교에 배정된 단지도 함께 빠진다.

| 학교 | 지역 | 영향 단지 |
| --- | --- | --- |
| 참미르초 | 광주 | 4 |
| 천안중앙초 | 충남 | 4 |
| 신연초 | 부산 | 3 |
| 무안희망초 | 전남 | 2 |

공식 API로 확인한 결과 더 새로운 자료가 없어, 출처가 다시 공시할 때까지는
고칠 방법이 없다. 우리 쪽 결함이 아니므로 다섯 개 지역을 무기한 막아두는 대신,
`etl/upstream_school_gaps.json`에 근거와 함께 등재하고 자동 검사가 **그 네 곳만**
예외 처리하도록 했다. 새로운 미연결은 여전히 검사에서 실패한다.

**(2) 단지 위치가 어느 통학구역에도 안 들어가서 — 20단지**

학구도 폴리곤 7,140개와 직접 대조해 원인을 쟀다. **폴리곤 안에 있는데 배정이
안 된 단지는 0건**이었다. 즉 맞춰 붙이는 과정 자체는 정상이고, 단지 위치가 정말로
모든 통학구역 밖에 있다. 다만 벗어난 정도가 문제다 — 가장 가까운 경계까지
최소 17m, 중앙값 72m다.

| 분류 | 기준 | 건수 |
| --- | --- | --- |
| 좌표 오차 수준 | 경계까지 30m 이하 | 6 |
| 학구 사이 틈 | 30m 초과, 주변 300m에 학구 2개 이상 | 11 |
| 학구 커버리지 밖 | 30m 초과, 주변 학구 1개 이하 | 3 |

30m는 건물 한 채 폭도 되지 않는다. 단지 대표 좌표가 건물이 아니라 지번 중심에
찍혀 도로 건너로 넘어간 것으로 보는 편이 자연스럽다. 부산진구 전포초 일대에는
네 단지가 47~76m로 몰려 있어, 단지 넷의 문제가 아니라 **그 지점 폴리곤 하나의
결손**이다.

세대 규모가 큰 두 곳이 여기 속한다 — 여수 힐스테이트죽림젠트리스(989세대, 21m),
전주 에코시티 데시앙 네스트 3블럭(830세대, 96m). 이 둘만으로 1,819세대다.

**경계에서 30~50m 벗어난 점을 가장 가까운 학구에 붙이는 방법**을 검토했으나
채택하지 않았다. 배정 규칙을 전국에 걸쳐 바꾸는 일이라, 지금 맞게 배정된
단지들까지 흔들릴 위험이 이득보다 크다고 판단했다. 원인은 기록해 두었고,
고친다면 좌표를 바로잡는 쪽이 먼저다.

**(3) 사람이 아직 확인해야 하는 것 — 1건**

부산 기장의 `(75-0)`은 주변 300m 안에 통학구역이 하나도 없는 유일한 단지다.
단지 이름이 지번처럼 읽히고 사용승인 연도도 없어, 통학구역을 보기 전에 **원본
단지 자료부터** 확인해야 한다.

**검수 결과 요약**

자동으로 뽑은 검수 대상 182건 중 **181건이 정상**으로 정리됐고 1건이 남았다.
대부분은 실제 문제가 아니었다 — 같은 단지가 두 유형으로 중복 계상되거나,
통학구역 이름이 해석되지 않았지만 걸린 단지가 하나도 없는 경우였다.

판정은 `etl/review_verdicts.csv`에 남아 검수표를 다시 만들어도 유지된다.
단지별 측정 결과는 [`operations/REVIEW_HELD_CASES.md`](operations/REVIEW_HELD_CASES.md),
다시 재려면 `python etl/measure_unassigned_points.py --all`.

**규모 감각**: 빠진 33단지는 전체 45,853단지의 **0.07%**다. 작은 숫자지만,
빠진 단지에 사는 사람에게는 "우리 아파트가 검색되지 않는다"는 뜻이므로
숨기지 않고 여기 적어둔다.

## 5. 배포 구조 (2026-09-28 변경)

### 어떻게 나가나

```
git push origin release   →   Vercel이 자동으로 빌드하고 사이트에 반영
```

이게 전부다. 그 외의 수동 절차는 없다.

### 왜 바뀌었나

전에는 앱 폴더를 손으로 복사해 임시 폴더에서 배포 명령을 실행했다. 그 이유는
**Vercel이 `main`이라는 브랜치를 보고 있었는데 실제 작업 브랜치는 `master`
였기 때문**이다. `main`은 프로젝트 생성 직후의 커밋 2개짜리 껍데기였다.

그래서 아무리 push해도 운영 배포가 일어나지 않았고, 사람이 손으로 올리는
방식이 굳어졌다. 부작용도 있었다.

- 배포 설정이 저장소 밖 사본에 있어서, 저장소의 올바른 설정이 쓰이지 않았다.
  이 때문에 **첫 화면 외의 모든 주소가 404**였다 (`/admin/etl` 포함)
- 그 수동 배포는 절반 이상 차단됐고, 될 때까지 재시도하고 있었다

운영 브랜치를 `release`로 옮기자 두 문제가 함께 사라졌다.

절차와 배경은 [`operations/DEPLOYMENT.md`](operations/DEPLOYMENT.md).

### 배포 후 항상 확인하는 한 줄

```bash
curl -s -o /dev/null -w "%{http_code}\n" https://wherecho.co.kr/admin/etl
```

`200`이면 정상, `404`면 배포 설정이 빠진 것이다.

## 6. 브랜치 규칙

```
master   ← 평소 작업. push하면 미리보기만 생긴다
release  ← 운영. push하면 실제 사이트가 바뀐다
```

**릴리스는 `master`를 `release`에 머지하는 일이다.**

```bash
git checkout release
git merge master     # 올릴 범위를 정해서
git push             # 이 push가 배포
```

`master`에 하루 열 몇 번 push하는 속도에서 push마다 운영이 바뀌면 안 되기
때문에 둘을 나눴다. **무엇을 언제 공개할지가 사람의 판단으로 남는다.**

되돌리기는 Vercel 대시보드에서 이전 배포를 승격(Promote)하면 된다. 저장소를
건드리지 않는다.

> 저장소는 `pjt_250826`이 루트이고 앱은 그 안의 `elementary-v2/`에 있다.
> 워크스페이스 최상단(`F:\sm\vibe\elementary`)은 git 저장소가 아니다.

## 7. 검증 게이트

무언가를 바꾼 뒤 통과해야 하는 검사다. `elementary-v2/`에서 실행한다.

```bash
npm run lint        # 코드 규칙
npm run typecheck   # 타입 오류
npm run build       # 실제로 빌드되는지
npm run browser:smoke:public -- http://localhost:4173   # 브라우저로 실제 동작 확인
```

**smoke 테스트**는 실제 브라우저를 띄워 사람이 하는 행동을 따라 한다 — 검색하고,
결과를 누르고, 필터를 걸고, 시트를 끌어올린다. 29개 항목을 확인한다.

일상 확인은 이 두 줄이 가장 편하다. `localhost`는 네이버 지도 허용 주소라
지도까지 그대로 보인다.

```bash
npm run build && npm run preview
```

ETL 쪽 검사는 별도다.

```bash
python -m unittest discover etl/tests      # 113개 테스트
python etl/audit_operational_backend.py --regions 서울특별시 경기도 인천광역시
                                           # 52항목, status=pass 여야 한다
python etl/check_capacity.py               # 용량이 예산 안인지
```

감사는 범위를 지정해 돌린다. 인자 없이 실행하면 공개된 17개 지역을 한 묶음으로
보려 하는데, 그런 묶음은 빌드된 적이 없어 파일을 찾지 못한다.

> `npm test`는 없다. 이 저장소에 JS 단위 테스트 실행기는 없다.

## 9. 조심해야 할 것들

지금까지 실제로 사고가 났거나 날 뻔한 지점이다.

| 함정 | 내용 |
| --- | --- |
| `archive/`가 안전하지 않다 | 운영 ETL이 `archive/` 안의 파일 두 개를 **실제 입력으로 읽는다.** 지우면 아파트 식별자가 바뀐다 |
| 검증이 조용히 무의미해진다 | smoke가 삭제된 문구를 검사하거나 첫 화면만 열면, 통과해도 아무 의미가 없다. 실제로 그래서 심각한 회귀가 며칠간 가려졌다 |
| `VITE_`로 시작하면 공개된다 | 빌드 결과물에 그대로 박힌다. Supabase anon 키는 거기 있어도 되지만(RLS가 보호), `SUPABASE_SERVICE_KEY`는 절대 안 된다 |
| 숫자를 문서에 고정하지 말 것 | 지역·행 수는 하루 만에도 바뀐다. 레지스트리와 Update Log를 본다 |
| 적용된 SQL을 다시 설계하지 말 것 | `06`~`17`은 이미 운영에 적용돼 있다 |
| 함께 바꿔야 하는 것들 | 스키마·공개 계약·TypeScript 타입·ETL 산출물·감사·문서는 **한 번에 같이** 바뀌어야 한다 |
| 이름으로 조회하지 말 것 | 단지명·학교명은 전국에서 유일하지 않다. 은마는 서울과 대구에 각각 있고, 같은 단지가 배정 자료에는 `근화희망타운1`, 공개 자료에는 `근화희망타운1차`로 적힌다. 조회는 `canonical_complex_id`나 `school_id`로 한다. 실제로 이 때문에 멀쩡한 단지를 "배정 없음"으로 잘못 판단한 적이 있다 |
| 테스트에 시점 사실을 넣지 말 것 | "아직 공개되지 않은 지역"을 범위 밖 표본으로 쓰던 테스트 두 개가, 17개 지역이 모두 공개되자 쓸 표본이 없어 깨졌다. 검수 건수를 숫자로 박아둔 테스트도 같은 이유로 깨졌다. 바뀌는 값이 아니라 지켜야 할 성질을 검사한다 |

## 10. 용어

| 용어 | 뜻 |
| --- | --- |
| ETL | 데이터를 가져와(Extract) 정리하고(Transform) 넣는(Load) 과정 |
| 마이그레이션 | 데이터베이스 구조를 바꾸는 SQL 스크립트. 번호 순서대로 적용한다 |
| RLS | 행 수준 보안. 누가 어느 행을 읽을 수 있는지 데이터베이스가 강제한다 |
| RPC | 데이터베이스에 미리 만들어 둔 함수를 앱이 호출하는 것 |
| anon 키 | 브라우저에 공개되는 열람용 키. RLS가 보호한다 |
| service_role 키 | 모든 제한을 무시하는 관리용 키. 절대 프론트엔드에 넣지 않는다 |
| 스냅샷 | 특정 시점의 원천 파일을 그대로 보관한 것 |
| 원자적(atomic) | 전부 되거나 전부 안 되거나. 중간 상태가 보이지 않는다 |
| 웨이브 | 지역을 한 번에 다 넣지 않고 나눠 넣는 단위 |
| smoke 테스트 | 실제 브라우저로 핵심 동작만 빠르게 확인하는 검사 |
| 딥링크 | 첫 화면이 아닌 특정 주소로 바로 들어가는 것 |
| rewrite | 어떤 주소로 들어와도 앱의 시작 파일을 돌려주게 하는 서버 설정 |
| canonical URL | 한 페이지의 **정식 주소**. 같은 페이지가 여러 주소로 열릴 때 어느 것이 진짜인지 정한 것 |
| canonical 태그 | 그 정식 주소를 검색엔진에 알려주는 `<head>` 안의 한 줄. 없으면 같은 페이지가 여러 개로 색인돼 평가가 갈라진다 |
| 301 리다이렉트 | 다른 주소로 들어온 사람을 정식 주소로 **실제로 보내는** 것. canonical은 보내지 않고 알려주기만 한다 |
| 슬러그 | URL에 쓰는 짧은 식별자. 이 프로젝트에서는 아파트마다 발급하는 불변 키를 뜻한다 ([ADR-007](decisions/ADR-007-immutable-public-identifiers.md)) |
