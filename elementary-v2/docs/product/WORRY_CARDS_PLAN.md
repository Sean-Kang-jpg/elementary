## 5. 카드 모델 (UX-19 최소안)

**새 화면을 만들지 않는다.** 고민 카드는 `src/content/guides/`의 가이드에 `worry` 필드를 더한 것이다. 가이드에는 이미 출처 검증(공식 출처 하나 이상), 확인일, 요약, 일정으로 가는 `nextStep`, 정적 페이지와 사이트맵이 있다. 새 경로를 만들면 프리렌더·사이트맵·canonical을 다시 맞춰야 해서 M 크기를 넘는다.

front matter에 더하는 것:

```yaml
worry:
  question: 돌봄에 떨어지면 하교 후는 어떻게 하나요   # 홈 고민 목록과 같은 문장
  situations: [1140, 1020]                             # 출발 계획 귀가 시각(분) 또는 dismissal
nextStep: {"label":"이 고민, 우리집 일정에서 풀어보기","href":"/timetable?face=week","kind":"plan"}
```

본문은 이 세 절을 이 순서로 갖는다: `## 알아두기`(공식 사실), `## 확인하기`(우리 학교·우리 집에서 볼 것), `## 다음 행동`(일정에 넣을 것).

`npm run content`가 막는 것(`scripts/build-content.mjs`):

- `worry.question`이 비었거나 40자를 넘음
- `worry.situations`가 비었거나 `RETURN_OPTIONS`(`schedule/starter.ts`)에 없는 값을 가짐
- 세 절 중 하나라도 없거나 순서가 다름
- `nextStep.kind`가 `plan`이 아님 — 고민 카드는 일정으로 끝난다
- `home-shelves.json`에서 이 가이드를 가리키는 고민의 `question`이 `worry.question`과 다름

화면에서 달라지는 것: 가이드 맨 아래 `nextStep` 버튼 문구가 "이 고민, 우리집 일정에서 풀어보기"가 된다. 홈 고민 목록은 지금 구조(`home-shelves.json`) 그대로 카드를 가리킨다.

**하지 않는 것(이번 범위 밖)**

- 시간표의 특정 칸(요일·시각)으로 바로 가는 주소. 지금 `/timetable`에는 그런 주소가 없고, 만들면 라우팅 변경이다. 첫 판은 한 주 면이나 입학까지 면으로 간다.
- 상황 태그로 카드를 거르거나 순서를 바꾸는 것. 태그는 검증과 이후 측정용으로만 둔다.
- 새 저장 키, 새 GA4 이벤트. 측정은 기존 `home_shelf_click`과 `plan_start`로 고민별 비율을 본다(백로그 7절).
