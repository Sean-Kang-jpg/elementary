# 우리집 일정 중심 UX 백로그

작성 2026-11-01. 상태: 방향 확정, 구현 전.
배경 논의: `wherecho_education_brand_conversation.md`(ChatGPT 세션 재구성본)와 2026-11-01 Claude 세션.
상위 방향: `PIVOT_V2_CONCEPT.md`. 작업 분담과 주고받는 방식: `docs/operations/CODEX_UX_HANDOFF.md`.

## 1. 포지셔닝

어디초는 학교 정보를 보여주는 곳이 아니라 **우리 가족의 초등생활 일정을 같이 만들고 시기마다 고쳐 가는 곳**이다.
학교 정보·가이드·돌봄·방과후·학원 데이터는 읽을거리가 아니라 일정에 넣을 재료다.

- 정답이 있는 것(일정·하교 시각·신청 기간)은 단정해서 답한다.
- 정답이 없는 것(학원 개수·활동 선택)은 순위 대신 **기본안**을 주고 고치게 한다.
- 순위는 우리 집 조건(시간·거리)으로만 매긴다. 인기·성적 순은 쓰지 않는다.
- 화면에서 "커리큘럼"이라는 말은 쓰지 않는다.

## 2. 확정한 것 (2026-11-01, 사용자)

| 항목 | 결정 |
| --- | --- |
| 중심 | 계획(우리집 일정)을 제품의 중심에 둔다 |
| GNB | 시간표 탭 → **우리집 일정**. 페이지 안은 "입학까지"(D-day) / "우리 아이 한 주"(시간표) 두 면. 내부 식별자와 URL(`timetable`, `/timetable`)은 유지 |

## 3. 설계 원칙

1. 모든 화면은 다음 한 걸음 하나로 끝난다.
2. 일정을 만들 때 입력은 두 번 고르기 이내. 나머지는 데이터로 채운다.
3. 저장은 기기에만(D1). 계정이 필요한 항목은 표시한다.
4. 홈은 고민으로 열고, 가이드·상세는 CTA로 닫는다. SEO 유입 대부분은 홈이 아니라 가이드·상세로 들어온다.

## 4. CTA 연결 시나리오

| 진입 니즈 | 들어오는 곳 | CTA | 도착 |
| --- | --- | --- | --- |
| 사립·국립 일정 | `/guide/private-national` | 우리 집 입학 일정 만들기 | 입학까지 (지원함) |
| 취학통지 | `/guide/school-notice` | 통지서의 학교로 하교·돌봄 보기 | 학교 상세 → 입학까지 + 한 주 초안 |
| 이사 | `move-*`, `when-to-move` | 이사 갈 집 배정 학교로 일정 만들기 | 검색 → 일정 |
| 배정 검색 | `/school/*`, `/apt/*` | 이 학교로 일정 만들기 | 한 주 초안 |
| 돌봄·방과후 | `care-afterschool`, `morning-care` | 우리 학교 돌봄 공백 계산하기 | 한 주 (안전 칸) |
| 입학 첫 주 | `first-weeks` | 첫 주 하교 시각, 우리 학교로 보기 | 한 주 (첫 주) |
| 추첨 결과 | 결과 이후 페이지 (신규) | 붙었다면 / 안 됐다면 다음 할 일 | 입학까지, 또는 공립 일정 |
| 막연한 고민 | 홈 고민 목록, 인스타 | 이 고민, 우리집 일정에서 풀어보기 | 해당 칸 |
