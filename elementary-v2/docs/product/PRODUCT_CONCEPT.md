## 1. 한 문장 정의

Elementary는 이사를 고민하는 가족이 **초등학교와 공식 배정 아파트를 함께
탐색하고, 후보지를 비교·저장·공유할 수 있는 의사결정 서비스**다.

## 2. 왜 이 제품이 필요한가

이 시장에는 이미 두 부류가 있고, 둘 다 한쪽씩만 해결한다.

| | 정확성 | 탐색·비교 |
| --- | --- | --- |
| 학구도안내서비스 (공식) | 공식 배정 그 자체 | 주소 단건 조회뿐. 역방향·비교·저장 없음 |
| 호갱노노·네이버부동산·아실 | **거리 기반** — 배정과 다를 수 있음 | 뛰어남 |
| **Elementary** | **공식 배정** | **탐색·비교·저장·공유** |

호갱노노는 "단지에서 가까운 초등학교 도보거리"를 보여준다. 이것은 배정이
아니다. 학부모가 가장 많이 하는 실수가 정확히 이 지점에서 발생한다.

**Elementary의 유일한 방어선은 "공식 배정 관계를 탐색 가능한 형태로 제공하는
유일한 서비스"라는 것이다.** 이 문서의 모든 결정은 이 문장을 지키는 방향으로
내린다.

## 3. 사용자에게 전달할 핵심 가치

> 우리 아이가 다닐 학교와 그 학교에 배정되는 아파트를 정확히 확인하고,
> 여러 후보를 한자리에서 비교하세요.

답해야 할 질문:

- 이 아파트에서는 어느 초등학교에 **배정**되는가? (가까운 학교가 아니라)
- 이 학교에는 어떤 아파트들이 배정되는가?
- 학교와 주거 규모는 어느 정도인가?
- 공동·복수 배정처럼 주의할 점은 없는가?
- 다른 후보와 비교하면 어떤 차이가 있는가?
- 가족과 공유할 정리된 자료가 있는가?

## 4. 핵심 사용자

**1차**: 초등학생 또는 예비 초등학생 자녀가 있고 1~3년 안에 이사를 고려하는
가족. 학교 서열이 아니라 실제 배정 가능성, 학교 규모, 선택 가능한 아파트,
주거 여건, 후보 간 차이, 배우자와의 합의를 원한다.

**2차**: 특정 아파트 입주 검토자, 부동산 중개·상담 과정의 학군 확인,
지역 조사자, 현재 거주지의 배정 관계를 확인하려는 학부모.

## 5. 핵심 사용자 상황

### 상황 A — 특정 아파트를 검토 중

아파트명 검색 → 배정 학교, 대표/추가 배정, 1학년 학생·학급 수, 함께 배정된
다른 아파트, 세대수·연식·주차, 배정 근거와 기준일.

다음 행동: 학교 상세 / 비슷한 아파트 / 후보 저장 / 비교 / 공유

### 상황 B — 특정 학교 주변으로 이사하고 싶다

학교명 검색 → 학교 규모, 학년별 학생·학급 수, 배정 아파트 지도와 목록,
아파트별 주거 정보, 공동·복수 배정 주의사항, 같은 지역 비교 학교.

다음 행동: 조건 필터 / 아파트 상세 / 비교함 / 후보 저장 / 공유

### 상황 C — 아직 지역만 정했다

지역 페이지 또는 지도 → 학교 분포, 규모별 구분, 배정 아파트가 많은 학교,
대단지·신축이 연결된 학교, 지역 데이터.

다음 행동: 관심 학교 발견 / 후보 탐색 시작 / 지역 내 비교

## 6. 제품의 세 가지 축

**발견** — 학교·아파트 통합 검색, 지역별 탐색, 지도, 조건 필터, 관련 후보
추천, 검색엔진용 공개 상세 페이지

**판단** — 학교 상세, 아파트 상세, 공식 배정 관계 설명, 비교, 불확실성 표시,
출처·기준일

**보관과 공유** — 후보 저장, 최근 본 항목, 비교 목록, 메모, 공유 링크,
공유용 요약, 데이터 변경 알림

## 7. 화면 모델 — 지도와 페이지의 관계

**v1 초안의 가장 큰 공백이었던 부분이다.** 현재 앱은 지도 위에 바텀시트를
겹치는 모바일 앱이고, 새 컨셉은 고유 URL을 가진 상세 페이지를 요구한다.
둘의 관계를 다음과 같이 정한다.

**같은 콘텐츠, 두 개의 표현. 표현을 결정하는 것은 진입 경로다.**

| 진입 경로 | 표현 | URL |
| --- | --- | --- |
| 지도에서 마커 탭 | 바텀시트 (지도 문맥 유지) | 주소창은 상세 URL로 바뀜 (pushState) |
| 검색 결과 선택 | 바텀시트 | 동일 |
| 외부 링크·검색엔진 진입 | **전체 화면 상세 페이지** | 정규 URL |
| 전체 화면에서 "지도에서 보기" | 지도 + 바텀시트로 전환 | 동일 URL 유지 |

원칙:

1. **URL은 하나다.** 바텀시트로 보든 전체 화면으로 보든 `/school/:id`는 같은
   대상을 가리킨다. 공유된 링크는 받는 사람의 진입 경로 규칙을 따른다.
2. **상세 본문은 한 벌만 만든다.** 바텀시트와 전체 화면은 같은 컴포넌트를
   서로 다른 컨테이너에 넣는다. 두 벌을 만들면 반드시 갈라진다.
3. **뒤로가기는 바텀시트를 닫는다.** 지도를 떠나지 않는다.
4. **비교 페이지는 지도가 없는 독립 전체 화면이다.** 바텀시트 표현을 갖지
   않는다.

기존 바텀시트 제스처 엔진([`../ux/FRONTEND_UX_SYSTEM_PLAN.md`](../ux/FRONTEND_UX_SYSTEM_PLAN.md))은
그대로 유지된다. 이 모델은 그 위에 URL 레이어를 얹는 것이지 대체하지 않는다.

## 8. 핵심 화면

### 학교 상세

상단 요약: 학교명·주소, 공립/사립, 1학년 학생 수, 1학년 학급 수, 학급당
학생 수, 배정 아파트 수, 데이터 기준일

본문: ① 학년별 학생·학급 ② 배정 아파트 지도 ③ 배정 아파트 목록
④ 공동·복수 배정 안내 ⑤ 비슷한 주변 학교 ⑥ 출처와 데이터 품질

고정 행동: 후보 저장 / 비교 담기 / 공유 / 지도에서 보기

### 아파트 상세

상단 요약: 아파트명·주소, 세대수, 사용승인연도, 세대당 주차, 배정 학교,
데이터 기준일

본문: ① 배정 학교 ② 복수 배정 여부 ③ 단지 기본 정보 ④ 같은 학교에 배정된
다른 아파트 ⑤ 인근 비교 후보 ⑥ 출처와 데이터 품질

> **선행 조건**: `school_apartment_serving`에는 현재 기준일 컬럼이 없다.
> 학교 쪽은 `reference_date`/`student_statistics_year`/`student_data_status`가
> 있다. 11절 원칙을 지키려면 ETL과 serving 계약에 아파트 기준일이 먼저
> 추가돼야 한다. `assignment_rank`는 이미 있어 복수 배정 표시는 추가 데이터
> 없이 가능하다.

### 비교 페이지

학교끼리, 아파트끼리만 비교한다. 이종 혼합 비교는 1차 범위에서 제외한다.

**학교**: 지역 / 설립 유형 / 학년별 학생 수 / 학급 수 / 학급당 학생 수 /
배정 단지 수 / 배정 총세대수 / 공동·복수 배정 주의 / 기준일

**아파트**: 배정 학교 / 세대수 / 사용승인연도 / 세대당 주차 / 공공임대 비율 /
복수 배정 여부 / 기준일

비교 결과는 URL로 보존하고 로그인 없이 공유한다.

> **선행 조건 (2026-09-27 검증 완료)**: `school_id`는 안정적이나
> `canonical_complex_id`는 그렇지 않다. URL과 측정에는 불변 공개 슬러그
> `complex_public_id`를 쓴다. [12절 0단계 항목 2](#0단계--착수-전-결정-구현-없음--2026-09-27-완료) 참조.

## 9. 첫 화면

기본 메시지:

> **어느 학교에 배정될까요?**
> 학교명이나 아파트명을 검색해 공식 배정 관계와 주거 정보를 확인하세요.

검색 예시: 서울대곡초등학교 / 래미안대치팰리스 / 강남구 초등학교

보조 진입: 내 주변 학교 / 지역으로 찾기 / 최근 본 후보 / 많이 찾는 학교

지도는 유지하되 첫 행동을 결정할 수 있게 검색 목적을 명확히 한다.

### 콜드스타트

"많이 본 학교", "최근 많이 본 항목", "최근 갱신된 지역"은 트래픽이 없는
초기에 빈 껍데기가 된다. **초기에는 데이터 기반 대체물로 채우고, 조회
데이터가 충분히 쌓이면 교체한다.**

| 최종 형태 | 초기 대체물 |
| --- | --- |
| 많이 본 학교 | 배정 단지 수 상위 학교 |
| 많이 본 아파트 | 세대수 상위 단지 |
| 최근 갱신된 지역 | 최근 ETL run이 갱신한 지역 (실제로 있는 데이터) |

교체 시점은 "해당 목록의 상위 10개가 모두 최소 조회수를 넘길 때"로 정한다.

## 10. 콘텐츠

콘텐츠는 뉴스가 아니라 보유 데이터를 해석한 탐색 입구다.
[`NEWS_CONTENT_CONTRACT.md`](NEWS_CONTENT_CONTRACT.md)의 계약을 따른다.

**지역 콘텐츠 (데이터에서 템플릿 생성)** — 강남구 초등학교와 배정 아파트,
분당구 1학년 규모별 학교 비교, 송파구 대단지의 배정 학교, 신축이 많이
연결된 학교

**질문형 콘텐츠 (수기 작성)** — 한 학교에 여러 아파트가 배정되는 이유 /
가까운 학교와 배정 학교가 다른 이유 / 공동통학구역이란 / 1학년 학생 수로
알 수 있는 것 / 아파트를 검색했는데 여러 학교가 나오는 이유

**데이터 변화 콘텐츠** — 새로 추가된 지역, 갱신된 학교 정보, 검토 중인 배정
사례, 기준일과 변경 사항

**생성 콘텐츠의 품질 하한**: 템플릿 생성 페이지는 페이지마다 고유한 수치와
문장을 가져야 한다. 같은 문장에 지역명만 바뀐 페이지는 만들지 않는다.
검색엔진의 저품질 대량 페이지 판정은 유입 전략 전체를 무너뜨린다.

모든 콘텐츠는 관련 상세 페이지로 연결한다.

## 11. 신뢰 원칙

1. **공식 배정과 거리를 구분한다.** 가까운 학교를 배정 학교처럼 표현하지
   않는다. 이것이 경쟁 서비스와의 유일한 차이이자 존재 이유다.
2. **불확실성을 감추지 않는다.** 공동통학구역, 복수 배정, 검토 필요 상태를
   사용자 언어로 설명한다.
3. **없는 값은 없는 상태로 보여준다.** 확인되지 않은 값을 0으로 표시하지
   않는다.
4. **기준일을 노출한다.** 주요 상세 페이지에 데이터 기준일과 출처를 표시한다.
5. **순위를 만들지 않는다.** 종합 점수나 추천 순위를 제공하지 않는다. 사용자가
   자신의 조건으로 비교하도록 사실과 맥락만 제공한다.

이 원칙은 브랜드명과 카피에도 적용된다. [13절](#13-브랜드) 참조.

## 12. 범위와 단계

### 0단계 — 착수 전 결정 (구현 없음) — **2026-09-27 완료**

검증 결과 전문은
[`../reference/REPORT_CONCEPT_PREFLIGHT_20260926.md`](../reference/REPORT_CONCEPT_PREFLIGHT_20260926.md).

1. **공개 지역 범위 — 확정.** 2026-09-27 기준 운영 공개는 서울·경기·인천·
   대전·울산·제주 **6개 광역, 초등학교 2,659교**. 레지스트리 전체는 17개 광역
   6,303교이고 나머지는 `planned`.
   지역 페이지와 지역 콘텐츠는 `status=production`인 지역만 대상으로 하며,
   그 목록을 **레지스트리에서 읽는다.**
   **숫자를 문서나 코드에 고정하지 않는다** — 이 검증 도중에도 4개에서 6개로
   바뀌었다. 위 숫자는 시점 기록이며 판단 근거로 쓰지 않는다.
2. **식별자 안정성 — 검증 완료. 조치 필요.**
   `school_id`는 교육부 부여 코드로 **안정**하다.
   `canonical_complex_id`는 K-apt 매칭 성공 여부에 따라 접두사가 바뀌며,
   20,164단지 중 `APT:`가 11,863개(58.8%), 재빌드 시 이동 고위험군이
   1,284단지(6.4%)다. 뿌리가 되는 아파트 기준자료도 2024-10자 고정 파일이라
   교체 시 `APT:` 전체가 이동한다.
   → **불변 공개 슬러그 `complex_public_id`를 도입하고 URL·측정에 그것만
   쓴다.** 1단계 첫 작업이다.
3. **SEO 렌더링 방식 — 결정.** 상세 경로 한정 서버리스 프리렌더.
   [`../decisions/ADR-006-detail-page-rendering.md`](../decisions/ADR-006-detail-page-rendering.md).
4. **화면 모델 — 확정.** [7절](#7-화면-모델--지도와-페이지의-관계).

### 1단계 — 공유 가능한 탐색 (MVP)

**순서가 곧 제약이다.** 아래 순서를 바꾸면 이미 색인된 URL이나 이미 쌓인
측정 데이터를 버리게 된다.

| # | 작업 | 왜 이 순서인가 |
| --- | --- | --- |
| 1 | **불변 공개 슬러그 `complex_public_id` 부여** | URL을 세상에 뿌린 뒤에 하면 색인된 주소를 전부 잃는다 |
| 2 | 라우팅 도입, 학교/아파트/지역 고유 URL, 지도 상태 URL 복원 | 1에 의존 |
| 3 | 상세 페이지 전체 화면 표현 + 동적 제목·설명 | 2에 의존 |
| 4 | 크롤러 대응 프리렌더 (ADR-006) | 3에 의존 |
| 5 | 공유 (URL 복사 + Web Share API), 최근 본 항목 | 2에 의존 |
| 6 | `public/` + `robots.txt` + `sitemap.xml` | URL 확정 후 |
| 7 | Google Search Console · 네이버 서치어드바이저 등록·제출 | 6에 의존 |
| 8 | GA4 설치 + 핵심 행동 이벤트 7종 | **라우팅 이후.** SPA에 먼저 붙이면 상세 조회가 집계되지 않는다 |
| 9 | 개인정보처리방침 페이지 | 8과 동시 배포 |

6~9의 상세는 [`MEASUREMENT_PLAN.md`](MEASUREMENT_PLAN.md).

### 2단계 — 비교 가능한 판단

- 학교 비교, 아파트 비교
- 관련 후보 추천
- 지역 탐색 페이지
- 아파트 기준일 컬럼 (8절 선행 조건)

### 3단계 — 지속되는 의사결정

후보 메모, 후보 그룹, 계정 기반 동기화, 데이터 변경 알림

### 4단계 — 데이터 확장

행동 데이터로 수요가 확인된 영역부터. 후보: 실거래가, 지하철 접근성,
학원 분포, 돌봄·방과후, 교육 프로그램.

채택 기준은 **"볼 수 있는 정보가 늘어나는가"가 아니라 "후보를 더 잘
판단하게 하는가"**다.

### 범위 밖 (1~3단계 내내)

회원가입, 이메일·푸시 알림, 사용자 리뷰, 학교 평가 점수, 개인화 추천
알고리즘. [`PRD.md`](PRD.md)의 out-of-scope 항목도 그대로 유효하다.

## 13. 브랜드

### 이름이 지켜야 할 제약

11절 원칙에서 직접 도출된다.

1. **근접성을 함의하면 안 된다.** "집앞", "근처", "동네", "품은" 계열은
   원칙 1을 이름에서부터 위반한다. (`초품아`는 검색량이 크지만 바로 이
   이유로 브랜드명이 될 수 없다 — 콘텐츠 키워드로만 쓴다.)
2. **서열을 함의하면 안 된다.** "베스트", "랭킹", "명문" 계열은 원칙 5 위반.
3. **지도로 자신을 한정하지 않는다.** 제품은 지도가 아니라 의사결정 도구다.
4. 네이버 검색에서 고유해야 하고, 한글 2~4음절, 도메인 확보가 가능해야 한다.

### 후보

| 이름 | 근거 | 약점 |
| --- | --- | --- |
| **어디초** | 사용자가 실제로 쓰는 질문 그대로. 첫 화면 "어느 학교에 배정될까요?"와 정확히 일치. 3음절, 검색 충돌 없음 | 다소 캐주얼 |
| **배정노트** | 저장·비교·공유라는 의사결정 도구 성격을 이름이 직접 설명 | 브랜드 매력 보통, "배정"이 단독으로는 모호 |
| **첫학교** | 정서적으로 강하고 확장 여지가 넓음 | 배정·주거 함의가 약함 |

### 권고: **어디초**

캐주얼함은 이 시장에서 약점이 아니다. 인접 시장 1위인 호갱노노가 훨씬 더
캐주얼한 이름으로 성공했다. "어디초"는 사용자가 이미 머릿속에서 던지고 있는
문장이고, 제품이 답하는 질문과 정확히 같다. 근접성·서열·지도 어느 것도
함의하지 않아 세 제약을 모두 통과한다.

보수적 선택이 필요하면 **배정노트**가 대안이다.

### 태그라인

> **어디초 — 학교와 집을 함께 고르는 법**
> 공식 배정 정보로 확인하고, 비교하고, 가족과 공유하세요.

v1 초안의 "초등 배정 지도"는 쓰지 않는다. 제품을 지도로 한정하는 동시에
제약 3을 위반한다.

## 14. 성공 기준

### 북극성 지표

**주간 유효 후보 탐색 세션 수** — 다음 중 하나 이상을 만족하는 세션:

- 학교 또는 아파트 상세를 2개 이상 열람
- 비교 화면 생성
- 후보 저장
- 상세 또는 비교 결과 공유

### 선행 지표 (4개만 추적한다)

1. 검색 결과 → 상세 도달률
2. 세션당 상세 페이지 수
3. 공유율 (상세 열람 세션 대비)
4. 7일 재방문율

### 측정 수단

현재 애널리틱스·개인정보처리방침·`robots.txt`·`sitemap.xml`이 모두 없어
위 5개 지표 중 계산 가능한 것은 **0개**다.

도구 세 가지를 쓰며 셋 다 무료다. **Search Console과 서치어드바이저가
GA4보다 먼저다** — SEO 작업의 성패는 색인 여부에서 갈리는데 GA4는 그것을
알려주지 않는다.

| 도구 | 답하는 질문 |
| --- | --- |
| Google Search Console | 구글이 색인했는가 |
| 네이버 서치어드바이저 | 네이버가 색인했는가 |
| GA4 | 들어온 사람이 무엇을 했는가 |

이벤트는 7종만 심는다: `search`, `select_search_result`,
`view_school_detail`, `view_apartment_detail`, `save_candidate`,
`share_item`, `create_comparison`.

**`entry_source` 파라미터가 가장 중요하다.** 상세 조회가 지도에서 왔는지
외부 링크에서 왔는지를 구분하며,
[ADR-006](../decisions/ADR-006-detail-page-rendering.md) 전체가 이 한 값으로
평가된다. `link` 진입이 늘지 않으면 프리렌더 투자는 실패한 것이다.

전체 정의·계산식·설치 순서는 [`MEASUREMENT_PLAN.md`](MEASUREMENT_PLAN.md).

**해석 규칙**: GA4는 광고 차단기에 일부 막히므로 절대값은 실제보다 작다.
모든 지표는 **추세로만** 해석하고 절대 방문자 수로 의사결정하지 않는다.

### 추적하지 않는 것

**체류시간.** 이 제품 사용자의 목표는 빨리 답을 얻는 것이다. 체류시간을
목표로 삼으면 답을 늦게 주는 UX에 보상을 주게 된다. 비교 과정에서 체류시간이
늘어난다면 그것은 결과이지 목표가 아니다.

그 밖의 지표는 위 5개로 설명되지 않는 현상이 생겼을 때 추가한다.
