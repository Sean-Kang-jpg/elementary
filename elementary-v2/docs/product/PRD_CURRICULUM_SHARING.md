# 커리큘럼 공유 — 따봉과 아이템 인기 (설계 초안)

Status: **1단계 구현 중** · 2026-10-05 · C-5~C-9 확정, 코드는 master에 있고 콘텐츠·운영 설정 대기

부모가 준비하는 아이의 커리큘럼(책, 영상·유튜브 채널, 장난감·교구, 학습지·앱, 수업)을
카드로 공유하고, **카드 안의 아이템 하나하나에 따봉**을 모아 "서울 5세 수학 1위 넘버블럭스" 같은
아이템 인기를 보여준다. 벤치마크는 오늘의집(사진 속 상품 태그 → 상품 인기)이다.

PRD v2의 Step 3(입학 이후 재방문 이유)에 대한 첫 후보다. 커리큘럼은 입학 뒤에도 이어지고,
4~7세로 유입 시점을 앞당긴다.

### 구현에서 바뀐 것 (2026-10-05)

**카드와 아이템은 DB 테이블이 아니라 저장소 콘텐츠다.** 1단계는 에디터만 쓰므로 가이드처럼
`src/content/curriculum/{items,plans,taxonomy}.json`에 두고 `build-content`가 검증한다(키 형식·중복,
없는 아이템, 분류 밖 값, 공식 url·확인일). DB(SQL `24`)에는 따봉과 **따봉이 가리킬 수 있는 키**
(`curriculum_refs`, 카드의 연령·지역·영역 포함)만 있다. 아래 2절 표의 `curriculum_items`·`curriculum_plans`·
모듈·플랜 아이템 테이블은 사용자 카드 단계(3단계)에서 다시 판단한다. 집계 테이블 대신 함수
(`curriculum_item_ranking`)로 바로 센다 — 규모가 작을 동안은 이쪽이 단순하다.

## 2. 구조

```
플랜(카드) ── 모듈(영역: 수학·영어…) ── 플랜 아이템 ──▶ 아이템 사전
   ▲ 따봉                                  ▲ 따봉          (넘버블럭스 = 하나)
```

**아이템 사전이 핵심이다.** "넘버블럭스", "Numberblocks", "넘버블럭스 시즌2"가 하나로 묶여야
순위를 셀 수 있다. 사전은 에디터가 관리하고, 사용자가 새 아이템을 넣는 단계에서는 '대기'로 들어간다.

### 테이블 (SQL `24` 후보)

| 테이블 | 공개 | 주요 컬럼 |
| --- | --- | --- |
| `curriculum_items` | 읽기 공개 (승인분) | `item_id`, `public_key`(불변, ADR-007 방식), `name`, `aliases[]`, `item_type`, `domains[]`, `age_min_months`·`age_max_months`, `external_refs`(유튜브 채널 ID·ISBN·브랜드), `status`(`approved`·`pending`·`merged`), `merged_into` |
| `curriculum_plans` | 읽기 공개 (게시분) | `plan_id`, `public_key`, `title`, `summary`, `child_age_months`, `region`, `district`, `weekly_hours`, `monthly_cost_band`, `author_kind`(`editor`·`user`), `author_id`, `status`, `published_at` |
| `curriculum_plan_modules` | 읽기 공개 | `module_id`, `plan_id`, `domain`, `position`, `note` |
| `curriculum_plan_items` | 읽기 공개 | `plan_item_id`, `module_id`, `item_id`, `position`, `months_used`, `note` |
| `curriculum_likes` | **비공개** (본인 행만) | `voter_id`(= `auth.uid()`), `target_type`(`plan`·`plan_item`·`item`), `target_id`, `item_id`(아이템으로 묶기 위한 사본), `created_at`. **UNIQUE(`voter_id`, `target_type`, `target_id`)** |
| `curriculum_item_popularity` | 읽기 공개 (집계만) | `item_id`, `age_band`, `region`, `domain`, `period`(`all`·`90d`), `voters`, `rank`. 주기적 재계산 |
| `item_external_signals` | 읽기 공개 | 인스타 스토리 투표 등 외부 신호. `source`, `count`, `measured_on`. **따봉과 합산하지 않고 따로 표기** |

- 날 투표 행은 공개하지 않는다. 누가 무엇에 눌렀는지는 집계로만 나간다
- 아이템 인기는 **아이템별 고유 투표자 수**다. 한 사람이 같은 아이템을 여러 카드에서 눌러도 1로 센다
- 공개 계약이 커진다. `DATA_CONTRACTS.md`에 SQL `23`처럼 기록한다

### 쓰기 권한 (RLS)

| 동작 | 누가 |
| --- | --- |
| 따봉 넣기·빼기 | 익명 포함 로그인 사용자, `voter_id = auth.uid()`인 행만 |
| 아이템·플랜 쓰기 (1단계) | 에디터만. 1단계는 저장소의 JSON을 스크립트로 올린다 — 아래 4절 |
| 플랜 쓰기 (사용자 작성 단계) | 정식 로그인 사용자, 본인 행만 |

## 3. 순위와 통계

- **표본 기준**: 고유 투표자 30명 미만인 칸(연령대 × 지역 × 영역)은 순위를 공개하지 않고
  "표본이 적습니다"로 표기한다. 기준 수치는 출시 전에 확정한다
- **기간**: 전체와 최근 90일 두 가지. 오래된 인기와 지금 인기를 나눠 본다
- **표기 원칙**: 순위 옆에 항상 투표자 수와 기준 기간을 붙인다. 외부 신호(인스타 투표)는 별도 줄
- **통계 페이지 후보**(표본이 쌓인 뒤): 연령별 영역 비중(5세 카드에서 수학 모듈이 차지하는 비율),
  유형별 비중(영상 vs 책), 월 비용 구간 분포. 모두 카드 데이터에서 나온다
- **조작 대응**: 익명 ID 발급 횟수 제한(Supabase 기본: IP당 시간당 30회), 익명 로그인에 로봇 확인
  (Cloudflare Turnstile), 집계에서 이상치 제외(짧은 시간에 한 아이템으로 몰린 신규 ID). 협찬과
  순위가 맞물리는 단계에서는 정식 로그인 사용자의 표만 순위에 반영하는 안으로 올린다

## 4. 1단계 — 에디터 카드와 아이템 순위

**콘텐츠는 코드로 관리한다.** 가이드처럼 `src/content/curriculum/` 아래에 아이템 사전과 플랜을 JSON으로
두고, 출처·확인일을 필수로 둔다. 스크립트가 DB에 올린다. 관리자 화면을 만들지 않아도 되고, 변경 이력이
git에 남는다.

| 산출물 | 내용 |
| --- | --- |
| 아이템 사전 | 처음 100~150개. 유형 6종 × 영역 8종 안에서 4~8세 대상 |
| 에디터 카드 | 20~30개. "에디터" 표기. 연령·지역·목표가 서로 겹치지 않게 |
| 화면 | 카드 피드, 카드 상세(아이템마다 따봉), 아이템 상세, 순위 |
| 투표 | 익명 로그인 + 따봉. 카드 따봉과 플랜 아이템 따봉 |
| 측정 | `like_item`, `like_plan`, `view_plan`, `view_item`, `view_ranking` |

### 화면과 주소

| 경로 | 화면 | 검색 유입 |
| --- | --- | --- |
| `/plans` | 카드 피드 — 연령·영역 필터 | |
| `/plans/{readable}--{KEY}` | 카드 상세 — 모듈별 아이템, 아이템마다 따봉 | 프리렌더 |
| `/items/{readable}--{KEY}` | 아이템 상세 — 연령별 인기, 이 아이템이 든 카드 | **프리렌더, 핵심 유입** ("넘버블럭스 몇 살") |
| `/ranking` | 순위 — 연령대·지역·영역 선택 | 대표 조합만 정적 페이지 |

주소 규칙은 학교·아파트와 같다(ADR-007). 마지막 `--` 뒤 키만 의미가 있고, 이름이 바뀌어도 링크가
살아 있다. 색인 후 주소를 바꾸면 비싸므로 **구현 전에 확정한다.**

### 내비게이션

하단 탭은 지금 홈·지도·입학 준비·MY 네 개다. 1단계는 **입학 준비 탭 안의 한 묶음**으로 시작하고,
반응이 확인되면 별도 탭을 검토한다.
