## 0. 한 문장으로

배정지도를 **예비초등 학부모를 정확히 모으는 유입 자산**으로 유지하고, 그 위에
**입학 준비 lifecycle 서비스**를 얇게 올려, 이 고객군과 직접 대화할 수 있는
경로를 확보한다.

> 어느 학교에 배정되는지를 알려주는 서비스
> → 그 학교에 입학하려면 지금 무엇을 해야 하는지 알려주는 서비스

## 1. v1.1에서 무엇이 바뀌고 무엇이 그대로인가

| | 컨셉 v1.1 (2026-09-27) | 차기 버전 (이 문서) |
| --- | --- | --- |

형태로 제공하는 유일한 서비스" — 는 이 문서에서도 유일한 방어선이다. 입학 준비
기능은 그 위에 얹는 층이고, 그것을 흔드는 방향으로는 만들지 않는다.

## 2. 왜 목표를 바꾸는가

배정지도의 강점과 한계는 이제 분명하다.

**강점** — 검색 의도가 극단적으로 명확하고, 실제 주거 의사결정 문제를 풀고,
학교·아파트·배정구역을 구조화할 수 있어 대량의 SEO 랜딩을 만들 수 있고, 예비초등
자녀를 둔 부모를 비교적 정확하게 걸러 유입시킨다.

**한계** — 배정 확인은 **저빈도 니즈**다. 한 번 확인하면 다시 올 이유가 약하다.
관심단지 저장이나 배정 변경 알림으로는 강한 retention이 만들어지지 않는다. 그리고
매물·가격·알림은 네이버부동산이 이미 매우 잘 하고 있어 재구현할 이유가 없다.

따라서 목표를 "학군 지도를 고빈도 서비스로 만든다"에서 **"고의도 고객군을 모으고
그들의 실제 문제를 탐색한다"**로 바꾼다. 당장 만드는 것은 완결된 서비스가 아니라
**Acquisition + Customer Discovery Infrastructure**다.

## 3. 타겟

### 1차 — 초등학교 입학을 앞둔 자녀를 둔 부모

"학군에 관심 있는 사람"이 아니라 **6~12개월 내 초등학교 입학이라는 이벤트를 앞둔
가족**으로 정의한다. 이벤트에는 날짜가 있고, 날짜가 있으면 D-Day와 다음 할 일을
만들 수 있다.

주요 상황: 다음해 입학 예정 / 현재 거주지 배정학교 확인 / 입학 전 이사 고민 /
사립·국립·공립 선택 / 늘봄·돌봄·방과후 탐색 / 준비물과 생활 준비 / 첫 사교육 선택 /
초1 생활 전반에 대한 불안.

### 2차 — v1.1의 1차 타겟

1~3년 내 이사를 검토하는 가족. **강등이 아니라 유입 경로다.** 이들이 배정지도의
검색 유입 대부분을 만들고, 그 중 입학이 임박한 가족이 1차 타겟으로 전환된다.
따라서 v1.1이 정의한 지도·상세·공유 경험은 축소하지 않는다.

## 4. 제품 구조 3단

### Step 1 — 우리 아파트는 어느 초등학교에 가나요?
배정지도. 검색 유입과 신뢰를 담당한다. **이미 있는 것.**

### Step 2 — 그 학교에 입학하려면 지금 무엇을 해야 하나요?
Elementary Start. 입학 프로필 · D-Day 로드맵 · 상황형 가이드 · 체크리스트 ·
콘텐츠 큐레이션. **이 문서가 정의하는 것.**

### Step 3 — 입학 이후에는 무엇이 필요한가요?
**지금 결정하지 않는다.** 실제 예비초등 학부모를 모아 질문·검색·클릭·콘텐츠 반응·
계산기 사용·오픈채팅 대화·공동구매 반응을 관찰한 뒤 결정한다. 이 문서에서 Step 3에
대한 유일한 요구사항은 **관찰 가능하게 만들어 둘 것**(11·12절)이다.

## 5. 네이버부동산과의 역할 구분

매물과 가격은 제품의 핵심 기능으로 만들지 않는다.

| 네이버부동산 | 우리 |
| --- | --- |
| 현재 매물, 실거래가, 호가, 신규매물·가격 알림 | **이 집에서 아이를 키우면 어떤 학교생활을 하게 되는가** |

우리가 다루는 것: 배정학교 · 통학 · 학교 환경 · 입학 준비 · 돌봄 · 교육환경.
단지 상세에는 가능하면 "네이버부동산에서 이 단지 매물 보기" 외부 링크를 둔다.
(외부 링크 정책과 표기 방식은 착수 전 결정 항목 — 14절 D6.)

## 6. 유지하는 것 — 기존 지도 기능

아래는 그대로 유지하며, **Elementary Start보다 먼저 완결돼야 한다.**

**아파트 기준** — 아파트 검색 / 배정 초등학교 표시 / 지도상 학구·배정 관계 /
관련 학교 상세 연결

**학교 기준** — 배정 아파트 / 위치 / 학생 수 / 학급 수 / 학급당 학생 수 /
학생 수 변화

또한 v1.1 1단계의 **잔여 항목이 이 버전의 선행 조건이다.** 특히:

- **4 · 크롤러 대응 프리렌더** — 유입 자산 전략 전체가 여기에 달려 있다.
  네이버·다음 크롤러는 JS를 렌더링하지 않는다.
- **5a · 공유 미리보기 썸네일**, **6 · 서치콘솔·서치어드바이저 등록**
- **7 · GA4 + 핵심 이벤트**, **8 · 개인정보처리방침**
- **9 · 최근 본 항목**, **10 · 지도 상태 URL 복원**, **11 · 상세 전체화면 표현**

유입 자산이 색인되지 않은 상태에서 Elementary Start를 만들면, 전환시킬 유입이
없는 전환 기능을 만드는 셈이다. 순서를 바꾸지 않는다.

## 7. 신규 기능 — Elementary Start

### 7.1 입학 프로필

사용자가 자신의 상황을 입력한다. **입력은 최소로 한다.**

| 항목 | 값 | 필수 |
| --- | --- | --- |
| 입학연도 | 연도 선택 | 필수 |
| 관심 유형 | 공립 / 사립 / 국립 (복수 선택) | 선택 |
| 현재 거주지역 | 시·군·구 수준 | 선택 |
| 이사 예정 | 없음 / 검토 중 / 예정 | 선택 |

원칙:

- **아이의 이름·생년월일·성별·학교명을 받지 않는다.** 로드맵 생성에 필요하지 않다.
- 거주지역은 **시·군·구 수준까지만** 받는다. 상세 주소는 받지 않는다.
- 입력 없이도 제품을 쓸 수 있어야 한다. 프로필은 게이트가 아니다.
- 저장 위치와 계정 여부는 **10절 결정 사항**이다.

### 7.2 입학 Roadmap

핵심 UI는 **D-Day + 이번 달 할 일** 두 덩어리다.

```
초등학교 입학 D-153

이번 달 해야 할 일
· 사립초 설명회 일정 확인
· 관심학교 결정
· 이사 여부 검토
· 현재 주소 기준 배정학교 확인      → 배정지도로 연결
· 돌봄 / 늘봄 정보 확인
· 입학 관련 추천 콘텐츠 확인
```

시간이 지나면 내용이 자동으로 바뀐다. 월별 흐름의 대략적 골격:

| 시기 | 축 |
| --- | --- |
| 9~10월 | 사립초 설명회, 학교 선택, 지원 전략 |
| 11월 | 사립초 지원, 추첨·결과 확인 |
| 12월 | 공립초 취학통지, **배정학교 확인 → 배정지도로 복귀** |
| 1월 | 예비소집, 입학 관련 행정 |
| 2월 | 늘봄·돌봄, 준비물, 학원, 생활 준비 |
| 3월 | 입학 |

**중요한 계약 두 가지.**

1. **위 시기는 예시이며 코드나 문서에 고정하지 않는다.** 취학통지·예비소집 일정은
   시·도 교육청과 연도에 따라 다르고 매년 바뀐다. 로드맵은 **연 1회 검증되는
   캘린더 데이터**로 관리하고, 검증되지 않은 시기는 "이 시기에 대체로 진행됩니다 —
   정확한 일정은 ○○에서 확인하세요"로 표시한다.
2. **갱신 책임자를 정한다.** 캘린더가 낡으면 이 기능은 틀린 정보를 주는 기능이
   된다. 갱신 주기·담당·검증 절차가 정해지기 전에는 출시하지 않는다. (14절 D3)

사립초 지원 결과가 나온 뒤 사용자는 자연스럽게 공립초 배정지도로 되돌아온다.
이 루프가 Step 1과 Step 2를 잇는 핵심 동선이다.

### 7.3 상황형 가이드 — 이사 예정자 입학 절차

**차별화 가능성이 가장 높은 영역이다.** 실제 질문들:

- 12월에 이사하면 취학통지서는 어디서 받는가
- 취학통지서를 받은 뒤 이사하면 어떻게 되는가
- 예비소집 전/후에 이사하면 어느 학교로 가야 하는가
- 새로 이사 갈 지역 학교에 언제 연락해야 하는가
- 전입신고만 하면 배정이 자동으로 바뀌는가

단순 FAQ가 아니라 **이사 시점별 안내**로 구성한다.

| 시점 | 제공 |
| --- | --- |
| 취학통지 전 이사 | 해야 할 일 |
| 취학통지 후 ~ 예비소집 전 | 해야 할 일 |
| 예비소집 후 ~ 입학 전 | 해야 할 일 |

공식 절차가 지역·시점에 따라 달라지는 부분은 **주민센터 / 교육청 / 학교 확인을
안내한다.** 우리가 절차를 확정해 주는 것처럼 쓰지 않는다 (8절 원칙 6).

가이드는 검색 유입 자산이기도 하므로 **고유 URL과 프리렌더 대상**이어야 한다.
(14절 D5)

### 7.4 입학 준비 체크리스트

사용자가 완료 여부를 체크하고, 그 상태가 저장된다.

**행정** — 취학통지 확인 / 예비소집 / 학교 홈페이지 가입 / 제출서류

**돌봄** — 늘봄 확인 / 돌봄교실 신청 / 방과후 일정 확인

**생활** — 등하교 동선 / 하교 후 돌봄 계획 / 비상연락 방식

**준비물** — 책가방 / 실내화 / 필통 / 연필 / 물통 / 우산 / 네임스티커 / 책상·수납

체크 상태의 저장 위치는 10절 결정 사항이다. **저장되지 않는 체크리스트는 만들지
않는다** — 체크가 사라지는 경험은 없는 것보다 나쁘다.

### 7.5 콘텐츠 큐레이션

모든 콘텐츠를 직접 만들지 않는다. 사용자의 **현재 단계에 맞는 자료를 소량**
추천한다.

> 이번 달 이것만 보세요.
> 책 1권 · 영상 1~2개 · 공식자료 (교육부 / 교육청 / 학교 / 늘봄 안내)

**2~4개만** 큐레이션한다. 나열은 하지 않는다. 상업적 링크가 포함되는 경우 8절
원칙 9를 따른다.

## 8. 신뢰 원칙 — v1.1 + 4개

v1.1 11절의 5개는 그대로 유효하다: ① 공식 배정과 거리를 구분한다 ② 불확실성을
감추지 않는다 ③ 없는 값은 없는 상태로 보여준다 ④ 기준일을 노출한다 ⑤ 순위를
만들지 않는다.

입학 준비 층에 다음 4개를 추가한다.

6. **공식 절차를 대체하지 않는다.** 취학·전학 절차 안내에는 항상 출처(교육청·
   주민센터·학교)와 확인 경로를 함께 둔다. 우리 문장이 행정 결정의 근거처럼 읽히게
   쓰지 않는다.
7. **추정치는 추정치로 표시한다.** 교육비·비용 계산기의 모든 출력에는 산출 근거와
   "추정" 표기를 붙인다. 실제 수강료가 공개되지 않은 항목은 범위 또는 평균으로
   제시하고, 개별 학원 가격을 단정하지 않는다.
8. **지역차·연도차를 명시한다.** 일정과 절차는 시·도 교육청별로 다르다. 확인되지
   않은 지역에 대해 확인된 지역의 값을 일반화하지 않는다.
9. **상업적 링크를 정보와 분리한다.** 제휴·공동구매·제품 추천은 정보 콘텐츠와
   시각적으로 구분하고 성격을 표시한다. 학교·아파트 상세의 사실 정보 안에는 넣지
   않는다.

## 9. 데이터 요건과 선행 조건

Elementary Start 기능 대부분은 **새 데이터를 필요로 하지 않는다** — 로드맵·가이드·
체크리스트·큐레이션은 콘텐츠와 클라이언트 상태다. 새 데이터가 필요한 것만 아래에
정리한다.

| 항목 | 원천 | 현재 상태 | 선행 작업 |
| --- | --- | --- | --- |
| 돌봄·방과후 운영 여부 | 학교알리미 공시 | **미검증.** 공시 항목 존재·커버리지·갱신주기 확인 안 됨 | 공시 항목 실증 → ETL → serving 계약 → `types/index.ts` + `SCHOOL_SELECT_FIELDS` + `sql/` 동시 변경 |
| 학생 수 추이 | 이미 보유 | 학년별 현재값 보유, **연도별 추이는 별도** | 과거 스냅샷 보존 여부 확인 |
| 입학 캘린더 (취학통지·예비소집·사립초 일정) | 교육청 공고 (수기) | 없음 | 캘린더 데이터 구조 + 연 1회 갱신 운영 절차 (D3) |
| 주변 학원 분포 | NEIS 학원·교습소 | 없음. **교습비 정보는 부분 공개** | MVP2. 정확도 한계를 먼저 실측 |
| 학교별 휴대폰 운영규정 | 학교 생활규정 문서 | 없음 | **보류** (13절) |

**공개 데이터 계약을 기억한다.** 브라우저가 읽는 테이블은 `school_master`와
`school_apartment_serving` 둘뿐이고 RLS가 이를 강제한다. 돌봄·방과후를 화면에
올리려면 serving 계층까지 값이 올라와야 하며, 프런트에서 다른 테이블을 조회하는
방식은 프로덕션에서 실패한다.

**지역 범위는 레지스트리에서 읽는다.** 운영 공개 광역 수는 계속 바뀐다 — 문서나
코드에 숫자를 고정하지 않는다. 입학 캘린더가 지역별로 다르다는 점과 맞물려,
**캘린더가 검증된 지역 = 로드맵을 제공하는 지역**이 된다. 미검증 지역에는 일반
안내만 노출한다.

## 10. 저장 · 계정 · 개인정보 — **결정 필요**

이 절이 이 문서에서 가장 중요한 미결 사항이다. v1.1은 **회원가입·이메일·푸시
알림을 1~3단계 범위 밖**으로 선언했다. 그런데 이 문서의 목표인 "직접 커뮤니케이션
가능한 audience 확보"는 어떤 형태로든 연락 경로 확보를 요구한다. **정면 충돌이므로
선택해야 한다.**

| 안 | 내용 | 얻는 것 | 잃는 것 |
| --- | --- | --- | --- |
| **A. 기기 저장만** | 프로필·체크리스트를 localStorage에. 연락 경로는 **외부 채널**(인스타·오픈채팅)로만 | 개인정보 처리 최소, 구현 최소, v1.1 범위와 충돌 없음 | 기기 간 동기화 없음, 우리가 audience를 직접 보유하지 못함 |
| **B. 기기 저장 + 선택적 이메일** | 위 + "입학 준비 알림 받기" 선택 입력 | 우리가 보유한 CRM 채널 | 개인정보처리방침 개정, 수집·이용 동의, 보관·파기 절차, 발송 수단 필요 |
| **C. 계정 도입** | 로그인 기반 동기화 | 완전한 lifecycle 추적 | v1.1 범위 밖 선언을 정면 파기. 예비초등 대상에 로그인 장벽은 전환 손실이 크다 |

**권고: A로 출시하고, B를 그 다음 릴리스에서 별도 승인 항목으로 다룬다.**

이유: (1) MVP의 목적은 audience 규모가 아니라 **니즈 검증**이고, 그것은 외부 채널
+ 행동 데이터로 충분히 관찰된다. (2) 이메일 수집은 기능 하나가 아니라 **동의·보관·
파기·발송이라는 운영 세트**이며, 지금 그 운영 역량이 없다. (3) 입학연도와
거주지역은 아동의 학령을 추정할 수 있는 정보다. 연락처와 결합하는 순간 처리 책임의
성격이 달라진다. 결합은 준비가 된 뒤에 한다.

A를 택해도 **개인정보처리방침 페이지는 선행 조건이다** — GA4 설치와 동시에
필요하다 (v1.1 1단계 8번).

## 11. 채널과 고객 리서치

### 자체 커뮤니티는 만들지 않는다

cold-start가 어렵고, 콘텐츠가 충분하지 않으면 빈 공간이 된다. 기존 채널을 쓴다.

| 채널 | 역할 |
| --- | --- |
| Instagram | discovery, 콘텐츠 유입 |
| 오픈채팅 | 실제 대화, 질문 수집 |
| 웹 | 검색 유입, 지도, 가이드, 체크리스트, 계산기 |

이후 이메일 또는 다른 CRM 채널 추가를 검토한다 (10절 B안).

### 질문 태깅

실제 사용자 질문을 수집해 태깅한다. 태그 후보: 사립초 / 국립초 / 배정 / 이사 /
예비소집 / 돌봄 / 늘봄 / 학원 / 교육비 / 준비물 / 책가방 / 휴대폰 / 친구관계 /
학교생활 / 맞벌이.

**이것은 수기 운영 작업이다.** 주 1회, 정해진 시트에 누적하고, 특정 태그가 반복
출현하면 별도 feature 또는 별도 product 후보로 승격한다. 승격 기준(예: 4주 연속
상위 3개 태그)을 먼저 정한다. 기준 없이 모으면 태그 목록만 쌓인다.

## 12. 측정

### 북극성 지표 — 교체

> **연락 가능한 예비초등 audience 수** (월간 누적)

정의: 다음 중 하나 이상을 만족한 식별 가능한 사용자 — 입학 프로필 생성 / 체크리스트
1개 이상 체크 / 외부 채널(인스타·오픈채팅) 가입 전환 / (B안 채택 시) 이메일 동의.

**v1.1의 "주간 유효 후보 탐색 세션 수"는 폐기하지 않고 유입 자산의 건강 지표로
남긴다.** 그것이 떨어지면 audience를 채울 원천이 마르는 것이므로, 두 지표를 나란히
본다.

### 선행 지표 (6개)

1. 검색 결과 → 상세 도달률 *(v1.1 유지)*
2. 상세 → Elementary Start 진입률 **(신규 — 유입 자산이 전환되는지)**
3. 프로필 생성 완료율
4. 로드맵 7일 재방문율 *(입학 준비층의 실제 반복 방문 여부)*
5. 공유율 *(v1.1 유지)*
6. 외부 채널 전환율 **(신규)**

### 이벤트

v1.1의 7종(`search`, `select_search_result`, `view_school_detail`,
`view_apartment_detail`, `save_candidate`, `share_item`, `create_comparison`)에
5종을 추가한다.

| 이벤트 | 파라미터 |
| --- | --- |
| `start_profile_created` | `entry_year`, `school_type_interest`, `moving_plan` |
| `view_roadmap` | `days_to_admission`, `entry_source` |
| `check_checklist_item` | `category`, `item_id` |
| `view_guide` | `guide_id`, `entry_source` |
| `channel_outbound` | `channel` (instagram / openchat) |

**`entry_source`는 계속 가장 중요한 파라미터다.** 가이드와 로드맵이 검색에서 직접
들어오는지, 지도에서 전환되는지를 구분한다. 이 값이 없으면 "지도가 유입 자산으로
작동하는가"라는 이 문서의 핵심 가설을 검증할 수 없다.

### 추적하지 않는 것

**체류시간과 DAU/WAU를 목표로 삼지 않는다.** v1.1의 판단을 유지한다. 이 제품
사용자의 목표는 빨리 답을 얻는 것이고, 입학 준비는 본질적으로 월 단위 리듬이다.
주간 활성도를 목표로 삼으면 리듬에 맞지 않는 UX에 보상을 주게 된다.

모든 지표는 **추세로만** 해석한다.

## 13. 범위

### MVP 1

**선행** — v1.1 1단계 잔여 항목 (6절). 특히 프리렌더·서치콘솔·GA4·처리방침.

**기존 유지** — 배정지도, 학교·아파트 상세, 검색, 필터, 공유

**학교 상세 보강** — 학생 수 / 학급 수 / 학급당 학생 수 / 학생 수 변화 /
돌봄·방과후 가능 여부 *(9절 선행 작업 완료 시. 미완이면 이 항목만 MVP2로 밀고
나머지는 진행한다)*

**Elementary Start** — 입학 프로필 / D-Day / 월별 로드맵 / 입학 체크리스트

**상황형 가이드** — 취학통지 / 예비소집 / 이사 시 절차 / 사립초 일정

**콘텐츠 큐레이션** — 책 / 영상 / 공식자료, 단계별 2~4개

### MVP 2 후보 — MVP 1 반응을 본 뒤 검토

학교 주변 학원 지도 / 학원 3개 선택 → 예상 월 교육비 / 초1 첫해 예상 비용 계산기 /
학교별 휴대폰 운영규정 / 준비물 공동구매 테스트 / **학교·아파트 비교** (부록 A-3)

공동구매는 수익이 아니라 **니즈 검증**이 목적이다. 저관여 입학 준비 상품(책가방,
네임스티커, 학용품 세트, 실내화, 물통, 우산)에 한정하고, **콘텐츠 → 수요 확인 →
공동구매** 순서를 지킨다.

### 당장 만들지 않는다

- 자체 부동산 매물·가격 알림
- 학원 셔틀 시간표, 학원별 실시간 수업 시간표
- 자체 학부모 커뮤니티
- **학생 스마트폰 보유율 추정, 기지국·유동인구 기반 학생 행동 추정, 임의의
  스마트폰 청정지수·청정학교 순위** — 정확도가 낮고 학생과 일반 유동인구를 분리할
  수 없다. 신뢰 원칙 ①·⑤ 위반이다.
- 학교 순위, 임의의 학군 점수 *(원칙 ⑤)*
- 키즈폰·스마트폰 직접 판매 — 통신사·개통·약정·보조금 구조가 복잡해 작은 서비스가
  직접 팔 수 없다. **콘텐츠로만 다룬다**: 초1 휴대폰이 필요한가 / 키즈폰 vs
  스마트워치 / 몇 학년부터 사주는가 / 학교에서는 어떻게 관리하는가.
- **휴대폰 규정 크롤러** — 문서 최신성 관리 부담, 정책 변화 가능성, 학교간 차이
  축소 가능성이 있고, 무엇보다 부모가 실제로 궁금해하는 "친구들이 몇 학년부터 폰을
  쓰는가"와는 다른 정보다. 관련 콘텐츠 반응이 확인된 뒤에 재검토한다. 그 전까지는
  학교 상세의 보조 정보 수준으로만 고려한다.

## 15. 리스크

| 리스크 | 왜 실제적인가 | 완화 |
| --- | --- | --- |
| **유입 자산이 색인되지 않는다** | 네이버·다음 크롤러는 JS를 렌더링하지 않는다. 프리렌더가 안 되면 전환시킬 유입 자체가 없다 | 6절 순서를 지킨다. 프리렌더가 MVP1의 실질적 선행 조건 |
| **캘린더가 낡는다** | 일정은 매년·지역별로 바뀐다. 낡은 로드맵은 신뢰를 직접 파괴한다 | D3. 검증된 지역만 로드맵 제공, 나머지는 일반 안내 |
| **계절성** | 입학 준비 수요는 9월~3월에 집중된다. 4~8월 지표 하락은 실패가 아니다 | 지표를 전년 동월 대비로도 본다. 비수기에는 배정지도·이사 검토층이 주 유입 |
| **저빈도 문제가 한 단계 뒤로 옮겨질 뿐이다** | 입학 준비도 결국 끝난다. 입학 후 재방문 이유는 이 문서에 없다 | 그것이 Step 3이며 **의도적으로 미결**이다. MVP1의 목적은 답을 내는 것이 아니라 답을 찾을 관찰 장치를 만드는 것 |
| **콘텐츠 운영 부담** | 가이드·큐레이션·태깅은 모두 지속적 수기 작업이다 | 항목 수를 의도적으로 제한했다(큐레이션 2~4개, 이벤트 5종, 태그 승격 기준). 늘리지 않는다 |
| **개인정보 범위 확대** | 입학연도 + 거주지역 + 연락처 결합은 책임 성격을 바꾼다 | D1에서 A안 권고. 최소 수집, 상세 주소·아동 정보 미수집 |

| # | 충돌 | 해결 |
| --- | --- | --- |
| 1 | **1차 타겟** — v1.1은 1~3년 내 이사 가족, 이 문서는 6~12개월 내 입학 가족 | 이 문서가 개정한다. v1.1의 1차는 **2차 = 유입 경로**로 재배치하며, 그들을 위한 지도·상세·공유 경험은 축소하지 않는다 (3절) |
| 2 | **북극성 지표** | 교체하되 v1.1 지표를 유입 자산 건강 지표로 병행 유지 (12절). D2에서 승인 |
| 3 | **2단계 우선순위** — v1.1은 비교 기능, 이 문서는 Elementary Start | Elementary Start가 2단계를 차지하고 **비교는 MVP2 조건부**로 이동한다. 근거: 비교는 2차 타겟(이사 검토층)의 기능이고, 1차 타겟의 의사결정은 "이 학교 vs 저 학교"보다 "지금 무엇을 해야 하는가"다. **단, 비교 기능을 폐기하지는 않는다** — 2차 타겟이 유입의 대부분이므로, 유입이 정체되면 비교가 다시 앞으로 온다 |
| 4 | **회원가입·알림이 범위 밖** vs **audience 확보** | 10절에서 A안 권고로 봉합. B안은 별도 승인 항목 |
| 5 | **v1.1 4단계 데이터 확장 후보**(실거래가·지하철·학원·돌봄·교육 프로그램) | 이 문서가 그 중 **돌봄·방과후를 MVP1로, 학원을 MVP2로** 끌어올린다. 실거래가·지하철은 그대로 4단계. 채택 기준은 v1.1과 동일 — "볼 수 있는 정보가 늘어나는가"가 아니라 **"판단·행동에 쓰이는가"** |
| 6 | **브랜드** | 변경 없음. **어디초** 유지. 태그라인은 입학 준비층을 포함하도록 별도 검토 (D8) |

**충돌하지 않는 것** — 신뢰 원칙 5개, 화면 모델(v1.1 7절 URL·바텀시트 관계),
식별자 정책(`complex_public_id`), 공개 데이터 계약, 콜드스타트 대체물, 생성 콘텐츠
품질 하한. 모두 그대로 적용된다.

## 부록 B: 원문 컨셉안 대비 조정 사항

입력된 컨셉안(2026-09-30)을 대부분 그대로 받았다. 바꾼 것만 적는다.

| 원문 | 조정 | 이유 |
| --- | --- | --- |
| MVP1에 돌봄·방과후 포함 | **조건부**로 변경 (D4) | 학교알리미 공시 항목 존재·커버리지가 검증되지 않았다. 공개 테이블 2개 계약 때문에 ETL→serving→types→sql 동시 변경이 필요하다 |
| 로드맵 월별 일정 명시 | 골격은 유지, **시기를 코드·문서에 고정하지 않음** | 지역·연도별로 다르다. 레지스트리 숫자를 문서에 고정했다가 바뀐 v1.1의 경험과 같은 문제 |

| 비교 기능 언급 없음 | **MVP2 조건부로 명시** | 누락과 의도적 후순위는 다르다. 되돌아올 조건을 적어 둔다 |

| 신규 기능 전반 | **프리렌더·색인을 선행 조건으로 명시** (6절) | 유입 자산 전략의 전제다. 원문에는 이 순서가 없었다 |
