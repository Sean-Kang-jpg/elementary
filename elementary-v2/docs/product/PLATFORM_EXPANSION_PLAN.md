# 어디초 서비스 개편 실행 계획

기준일: 2026-10-05. 대상: 만 5~7세 부모, 입학 D-18개월부터 입학 직후.

기준 자료: 최초 개편 요청, 사용자가 첨부한 「어디초(wherecho.co.kr) 서비스 개편 방향 및 Work 실행 가이드」 0~25절, [코드 감사 보고서](PLATFORM_EXPANSION_AUDIT_20261005.md).
이 문서는 목표·순서·완료 조건을 정의한다. 실제 완료 체크는 [OPERATION_PLAN.md](../operations/OPERATION_PLAN.md#platform-expansion) 한 곳에서 관리한다. 첨부 가이드의 구체적인 최종 IA를 기존 감사 초안보다 우선한다.

## 1. 확정된 방향

목표는 예비초등 부모의 입학 의사결정 플랫폼이다. Needs Precision × Timing Precision을 기준으로, 현재 질문 해결과 다음 질문 발견을 연결한다.

**2026-10-08 개정 — 학습 준비 추가, 5개 메뉴.** 사용자 결정으로 GNB를 **홈 / 학교 찾기 / 입학 준비 / 학습 준비 / MY**로 바꾼다. 같은 날 홈 탭을 잠시 보류했다가 **홈을 그대로 두고 5개로 확정**했다. 학습 준비는 콘텐츠가 준비되기 전 '준비 중' 화면으로 함께 배포한다(사용자 결정, §2의 빈 메뉴 원칙에 대한 예외). 같은 날 앞서 결정된 이름(입학 행정 대신 `입학 준비`)을 유지하고, 기존 계획에서 `입학 준비`였던 학습·생활 준비 콘텐츠는 새 메뉴 `학습 준비`로 옮긴다. Audit 2 §3의 "시간표 탭 없음, MY 안에서 시간표"는 아래처럼 바뀐다: 시간표 **조회**는 학습 준비(공개), 내 학교 기준 **적용·대안**은 MY(로그인).

| 메뉴 | 역할 | 공개 | 로그인으로 보내는 행동 | 경로 |
|---|---|---|---|---|
| 홈 | 배정 검색창 + 입학연도·할 일 요약 (현행 유지) | 전부 | — | `/` |
| 학교 찾기 | 주소/아파트/학교의 배정 확인과 이사 판단 | 지도·검색·학교/아파트 상세 | **관심학교 지정, 내 학교 지정** | `/map`, `/school/*`, `/apt/*`, `/area/*` 유지 |
| 입학 준비 | 입학 행정: 일정·취학통지서·예비소집·전입/이사·유예 등 Official/Timing 정보와 체크리스트 | 가이드·FAQ·체크리스트 열람 | **내 체크리스트 등록하기** | `/guide`, `/guide/*`, `/faq`, `/checklist` 유지 |
| 학습 준비 | 학습 가이드(환경/습관/배움) + 학교별 초1 시간표 조회("초1 하루 예상") | 가이드·학교 시간표 조회 | **시간표 짜기** | 신규 `/learn` — 2026-10-08 확정(기존 `/prep` 후보 대체) |
| MY | 내 학교 기준 개인 시간표, 시간 관리가 필요한 구간의 대안, 내 학교 소식, 저장·진행 | 로그인 안내 + 기존 기기 기록 | 메뉴 자체 | `/my`, `/favorites` 호환 |

HOME은 별도 원본 콘텐츠나 진행상태 저장소를 만들지 않는다. Community는 콘텐츠 안의 참여 기능으로 시작한다. 4분류 중 **환경·습관·배움은 학습 준비**, **선택·준비물은 입학 준비**(학교 안내 이후에 사는 물건이라 행정 시기와 묶임)로 둔다 — 2026-10-08 사용자 확정.

학교/지도/모든 콘텐츠 열람은 비로그인 공개다. 위 표의 행동에서 로그인으로 보낸다. 기존 브라우저 저장 기록(학교·아파트 즐겨찾기, 체크리스트 진행)을 보존하며, 로그인 취소 시 읽던 화면과 미완료 행동을 잃지 않는다. 로그인 후 실행할 행동은 중복 없이 복원한다. **로그인 게이트는 로그인이 실제로 켜진 뒤(P3)에만 적용한다** — 지금 카카오/구글 provider가 꺼져 있어, 먼저 게이트를 걸면 현재 되는 즐겨찾기가 막힌다.

### 1.1 MY — 내 학교 기준 시간 관리

내 학교(1곳)와 관심학교(여러 곳)를 구분한다. 내 학교를 지정하면:

1. 그 학교의 초1 요일별 예상 하교(A2-R04 데이터)를 주간 시간표에 깔고, 돌봄·방과후를 선택해 얹는다 (A2-S02 엔진).
2. 하교~보호자 귀가 사이처럼 비는 구간(A2-S07 미계획 구간)을 찾아 **대안**을 보여준다: 학교 돌봄(기본 종료/저녁·연장 분리, 정원·선발제 안내), 방과후, 다함께돌봄·지역아동센터(`nearby_care_centers`), 주변 학원 수(`apartment_academy_summary`/학원 RPC). 대안은 정보 제공이며 상담·중개·입점·결제는 범위 밖(Audit 2 제외 범위 유지).
3. 관심학교로 바꿔 보면 같은 계산을 다른 학교 기준으로 비교한다.

### 1.2 내 학교 소식 — 학교 사이트·공시 연동 (2026-10-08 추가 요청)

| 항목 | 출처 | 가능성 | 방식 |
|---|---|---|---|
| 학교 홈페이지 | NEIS 학교기본정보 `HMPG_ADRES` | **이미 공개 중** (`school_master.homepage`) | 바로 링크 |
| 급식 메뉴 | NEIS 급식식단정보 API | 높음 (NEIS 키 보유, 학교코드 crosswalk 59/60) | 조회 시 API 또는 일 단위 캐시 |
| 학사일정 | NEIS 학사일정 API | 높음 (A2-E03에서 실제 응답 확인) | 위와 같음 |
| 공시자료 (시정표·방과후/돌봄 계획 등) | 학교알리미 | 확인됨 (A2-E04-c, A2-R02) | 이미 수집 중인 항목부터 요약 + 원문 링크 |
| 가정통신문 | 학교 홈페이지 게시판 | **조건부** — 학교·교육청마다 게시판 구조가 다르고 첨부가 HWP 위주 (A2-E04-a에서 3게시판 probe만 검증) | 제목·날짜·원문 링크 목록까지. 본문/첨부 재게시는 하지 않음(§3 Research 원칙과 같음). 지원 게시판 유형부터 단계 확대 |

가정통신문은 2월 1기 방과후 안내(A2-R02b, E04-d)와 같은 수집 경로를 쓴다. 지원하지 못하는 학교는 홈페이지 링크로 대체한다.

### 1.3 결정 기록 (2026-10-08)

- **관심학교 = 기존 별표**(여러 곳). **내 학교 = 학교 상세의 새 버튼**(한 곳, 다른 학교를 고르면 교체). MY 시간표·내 학교 소식은 내 학교 기준, 관심학교로 바꿔 비교. 별표의 로그인 연결과 기존 기기 저장 이전, 내 학교 버튼은 로그인과 함께 출시. 데이터는 P3-01 `user_school_interests`에 관계 구분(interest/my_school).
- **가정통신문 = 내 학교로 등록된 학교만, 로그인 사용자 요청 시 호출.** 브라우저 CORS 때문에 서버 함수 경유, 학교 단위 캐시(수 시간)로 같은 학교 요청을 한 번으로. 규칙은 학교가 아니라 게시판 플랫폼 유형별(교육청 공통 플랫폼). 미지원 유형은 홈페이지 링크. 제목·날짜·원문 링크만, 유형별 robots.txt·이용약관 확인. 전체 학교 사전 수집은 하지 않는다.
- GA4 맞춤 측정기준은 다른 항목과 함께 나중에 등록. Search Console sitemap 재제출은 다른 팀원 작업 뒤. 돌봄 자료의 정기 ETL 편입은 추출 규칙 자동화(E05) 뒤 — 그 전까지 월간 수동.

학교 ID·아파트 공개키·체크리스트 ID·기존 URL·ETL/수동검수는 보호 대상이다. archive의 두 운영 입력 CSV도 그대로 보호한다. 신규 제품 기능은 배정 데이터 산출 과정을 바꾸지 않는다.

## 3. 콘텐츠와 Research 실행 기준

첫 seed는 **24개(환경 6 / 습관 6 / 배움 8 / 선택·준비물 4)**로 UI와 편집 흐름을 검증한다. 아래는 조사 주제이며 아직 검증된 결론이나 발행 콘텐츠가 아니다.

| 분류 | 첫 조사 주제 |
|---|---|
| 환경 6 | 거실서재, TV 유지/제거, 책상 위치, 낮은 책장, 현관 등교 준비존, 작은 집 공간 구성 |
| 습관 6 | 아침 준비, 전날 가방 챙기기, 자기 물건 정리, 수면 루틴, 영상 종료/활동 전환, 읽어주기 루틴 |
| 배움 8 | 입학 전 한글, 자기 이름 쓰기, 초1 수학 범위, 손가락/구체물 수놀이, 영어 노출, 쉬운 영어 영상 선택, 오디오/독서, 규칙·차례 보드게임 |
| 선택·준비물 4 | 책가방 선택 시기, 책상 구매 시기, 학교 안내 후 살 준비물, 물병·실내화 선택 |

이후 **환경 25 / 습관 25 / 배움 30 / 선택·준비물 20 = 100개**로 확대한다. 배움의 30개에는 한글/국어·수학·영어 노출·독서·영상·오디오·교구/보드게임을 모두 포함한다. 기존 쉬운 대화/건전성/Vocabulary 중심 YouTube 조사 자료는 위치와 유효성을 확인해 재사용한다. 자료 존재를 추정해 채우지 않는다.

공통 템플릿: 질문형 제목 → 어디초 요약 → 긍정 이유 → 부정 이유 → 조건부 판단 → 외부 반응 분석 → 부모 Poll → 한줄 경험 → 관련 콘텐츠/다음 Need. 조사 전에는 부모 후기나 빈도를 만들어 넣지 않는다. 실제 투표가 없으면 참여 0명/첫 참여 안내를 표시하고 인기라고 부르지 않는다.

행정 범위: 전체 일정, 취학통지서, 예비소집, 입학식, 전입/전출, 입학 전 이사, 조기입학, 유예/면제, 지역 차이, FAQ. 입학년도·발생 시기·전국/지역 범위·공식 출처·검증일·관련 학교/지역·다음 행동을 구조화한다. 부모 의견과 공식 사실을 화면에서 구별한다.

Research는 네이버·YouTube/댓글·Instagram·상품 후기를 출처로 살펴보되 원문/댓글을 재게시하지 않는다. source URL/title/type, published/analyzed date, positive/negative/conditional signal, 대상 연령·상황, 관측 표본/반복 빈도, 협찬·파트너스·광고 flag, notes를 기록한다. 광고성 리뷰는 핵심 평가 근거에서 제외하거나 명확히 별도 표시한다. 접근할 수 없는 자료는 확인 불가로 남긴다.

초1 교육과정을 기준으로 학습 필요성을 설명하고 영어 노출은 초1 정규교과 준비와 분리한다. 아이 성취·선행 수준·학원 수를 비교하거나 과시하는 구조를 만들지 않는다.

## 4. 데이터·인증·MY 설계 작업

schema 초안은 감사 문서에 있다. P0에서는 실제 테이블·컬럼·FK·policy·grant·RPC·auth provider를 읽기 전용으로 대조한다. 저장소 SQL만 보고 운영 적용 여부를 확정하지 않는다.

| 계약 | 다음 설계/구현 |
|---|---|
| 사용자 | 기존 `auth.users` 활용, `profiles`에 입학년도·관심지역; `user_school_interests`에 기존 school ID 참조 |
| 콘텐츠 | `contents`, `content_sources`, `tags/content_tags`; category/subcategory/title/summary/age/entry-year/timing/region/school/type/editorial-status/last-updated/source-count |
| 열람/저장 | `content_views`, `content_saves`; 비로그인 seen은 기기 상태, 계정 상태로 병합 시 동의·범위·보관 정책 명시 |
| Poll/Reaction | `polls/options/votes`, 주제별 단일 선택과 유용성 반응의 계약; option이 해당 poll 소속임을 DB에서 보장 |
| 경험/댓글 | `experiences`, `comments` 범위와 공개 projection, 신고/검수/숨김/삭제; 개인 프로필·투표자 ID 공개 금지 |
| 체크리스트 | `checklist_items`, `user_checklist_states`; 기존 17개 ID 유지, 신규 4분류 준비 항목 매핑 |

RLS는 사용자별 CRUD를 검증하고 다른 사용자 접근/소유자 변경을 차단한다. 공개 콘텐츠는 발행본만 읽으며 작성·검수 권한을 분리한다. 집계 설계는 기본 RLS가 타인 row를 숨긴다는 점까지 고려해 검토한다. `security_invoker`만 붙여 전체 집계가 된다고 가정하지 않는다.

Auth는 Kakao → Google 순으로 구성한다. 기존 익명 투표 identity 연결과 이미 존재하는 계정에 로그인하는 경우의 병합을 구분한다. 저장은 합집합, 프로필 충돌은 사용자 선택, 체크 완료/취소 충돌은 갱신 시점과 병합 규칙을 정한다. 아파트 저장도 계속 복원해야 한다. 재실행 가능한 이전과 실패 복구를 검증한다.

MY는 입학연도/D-day/관심학교·지역, 행정 진행, 환경·습관·배움·준비물 진행, 저장 콘텐츠, 참여 Poll, 한줄 경험, 최근 본 콘텐츠를 묶는다. 기능 도입과 함께 기존 개인정보 안내의 ‘기기에만 저장’ 문구를 실제 동작에 맞춘다.

## 5. 추천과 측정

추천 입력: entry_year, 관심학교/지역, viewed/unseen/saved/voted, category_interest. 후보: 안 본 콘텐츠, 비슷한 부모 인기, 관련/함께 보는 학교, 최근 반응 증가, 이번 시기 행정, 신규 분석. 처음에는 규칙으로 선정하며 원본 콘텐츠를 HOME에 복제하지 않는다.

집계가 부족하면 최신/시기/편집 추천을 이유와 함께 표시한다. 비슷한 부모 집계는 최소 표본과 기간을 정의한다. 주변 학교는 배정학교와 같다는 인상을 주지 않는다. 로그아웃·관심 미설정·모두 열람·API 실패에도 유효한 후보를 제공한다.

이벤트 계약: `school_search/view/save`, `admin_content_view/complete`, `prep_content_view/complete`, `content_save`, `poll_vote`, `experience_create`, `comment_create`, `login_start/complete`, `recommendation_impression/click`, `my_view`, `checklist_update`.

기존 이벤트와 매핑하여 중복 집계를 막는다. 조회와 완료를 구분하고 추천 impression은 실제 노출에서 기록한다. 개인정보·정확주소·자유 입력은 analytics에 싣지 않는다. 각 이벤트의 발화 조건, 속성, 중복 제거, 집계 분모/기간을 측정 문서에 정의한다.

핵심 funnel: Search/SEO → 학교찾기 → 배정 확인 → 다음 Need → 행정/준비 열람 → Poll/Reaction → Save → Login → 입학년도/관심학교 → HOME 발견/MY 진행. 질문 해결률·다음 콘텐츠 이동·저장/참여·로그인 후 행동 복원·행정/준비 완료를 우선하고 DAU/Retention은 보조 지표로 본다.

## 6. 단계별 운영 방식

각 TODO는 구현물과 검증 근거가 모두 있어야 체크한다. 계획 작성, 코드 존재, 로컬 검증, 운영 적용을 다른 항목으로 관리한다. 완료 때 날짜·파일·명령 최종 결과를 기록하고 실패·미확인은 열린 상태로 유지한다.

프런트 변경은 lint/typecheck/build와 명시 URL의 public smoke 최종 종료를 확인한다. 지도는 허용 도메인에서 검증한다. 모바일 360/390/430px 및 데스크톱, 뒤로/앞으로/새로고침, 저장 복원, Auth 취소, 네트워크 오류를 확인한다. DB 변경은 allow/deny 테스트와 실제 적용 후 조회를 확인한다.

배포 전 URL 목록·canonical/OG·sitemap·기존 지역 샘플을 비교한다. git root의 Vercel 설정과 `master`→`release` 운영 절차를 따른다. 배포/DB 적용은 변경 범위·복구 절차를 준비한 뒤 진행 상태를 별도 기록한다.

P6/P7은 현재 자동 구현 대상이 아니다. 사진/긴 글은 실사용과 운영 가능성, 사업 확장은 반복 문제와 수요가 확인된 후 검토한다. 초기 할인/구매 CTA·배너·영상학습 lead 판매를 KPI로 두지 않는다.
