## 지켜 주실 것

- 결과는 `etl/runtime/llm_extraction/outputs_afterschool/pivot_gyeonggi/`에 둔다. 파일럿 브랜치는 이 폴더를 읽기만 한다.
- **맹검 검증은 표본만.** 전체 맹검은 추출과 같은 양의 토큰이 더 든다. ①의 5곳은 파일럿 브랜치가 원문 대조로 검수하고(P2와 같은 방식), ②는 5곳 표본만 맹검한다.
- v3 시험에서 남은 문제(특수학급 강좌 포함, 기수별 같은 반 중복, 여러 반을 합친 운영 시간대)는 경기에도 나올 수 있다. ①에서 보이면 ② 전에 규칙을 정한다.
- 운영 적재는 **사용자 확인 뒤**. 적재기의 '기존 학교 빠지면 중단' 안전장치(gap37 작업, `82c627c`)가 들어간 `master`에서 돌린다.
- 적재 명령에는 기존 서울 출력 전부(`seoul`, `seoul_retry`, `seoul_noas`, `seoul_gap37_reviewed`, 맞춤형 `outputs_custom/seoul`·`seoul_noc` 등)를 함께 넣는다. 전체 교체 적재라 빠진 출력의 학교는 지워질 뻔하고, 안전장치가 그때 멈춘다.

## 파일럿 브랜치가 하는 일

- ①의 5곳을 원문과 대조 검수해 `docs/research/pivot/p1_review_*.json`으로 돌려 드림. 통과 여부도 함께 적는다.
- 하교 예상(P2)은 파일럿 브랜치 담당이고 운영 반영을 마쳤다(파일럿 298곳 중 235곳). 방과후 테이블은 건드리지 않는다.

## 연락

### 2026-10-23 검수 기준 보완 (사용자 승인)

방과후 강좌의 선택 단위와 맞춤형·돌봄 안의 활동 행을 구분한다. `course_choice`(강좌·반별 신청), `class_day_bundle`(반·요일 단위 맞춤형), `care_activity`(돌봄 입급 내 활동)로 검수 sidecar에 기록한다. 원시 14칸은 유지한다. 독립 초1 맞춤형의 요일·시각과 목록 완전성은 필수 조건을 유지한다. 돌봄 내부 활동의 미공시 세부 일정은 경고로 보존하고, 별도 근거로 돌봄 이용시간·참여 조건을 검수한다. 내부 활동을 독립 선택 강좌로 표시하면 안 된다. 기존 v1/v2 검수 기록은 이력으로 유지한다.

이는 조사·추출 검수 기준이며 운영 적재 승인이 아니다. 참여 단위가 연결된 로컬 미리보기를 검수한 뒤 운영 loader/화면에 이를 반영해야 한다. `etl/pivot_p1_participation.py`가 로컬 미리보기를 만들며, 기존 SQL 적재기의 원시 행 개수만으로 실제 신청 가능한 강좌 수를 판단하지 않는다.

진행 상황은 `docs/operations/PIVOT_PILOT_ETL.md`의 '진행 상황' 표에 적어 주세요. 범위가 바뀌면 매니페스트를 다시 만들어 알려 드립니다.
