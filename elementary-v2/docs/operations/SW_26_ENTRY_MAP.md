# SW-26 후속 · 시간표 첫 진입과 학교 미선택

## 화면과 저장

- 저장한 초안이나 고른 학교가 없는 첫 화면에는 예시 빈 시간 지도를 표시합니다. 하루·한 주와 요일은 예시 안에서 바꿀 수 있습니다. 예시의 하교·일정·빈 칸은 편집 동작이나 저장 경로에 연결되지 않습니다.
- 학교 칩은 바로 검색 시트를 열고, ‘학교 없이 시작’은 한 번에 학교 미선택 격자를 엽니다. 저장 안내는 ⋯ 시트에 한 줄로 있습니다. 시간표 탭과 ⋯의 입학까지 진입을 제거했고 MY 및 `/timetable?face=timeline` 진입은 유지됩니다.
- 학교 미선택 격자는 하교 미정과 귀가 질문으로 시작합니다. 하교선을 눌러 12:50·13:40·14:30을 고르면 직접 입력으로 표시하며, ‘잘 몰라요’를 눌렀을 때 13:40 가정을 저장합니다. 첫 하교 답은 평일 기준이며, 이후에는 고른 요일의 하교를 수정합니다. 빈 시간은 두 기준이 생긴 뒤 표시합니다.
- 기존 `elementary-schedule-plans-v1`의 `starter`와 일정 구조를 재사용합니다. 학교 선택 시 이전처럼 직접 입력한 일정을 가져올 수 있고, 학교 미선택에서 입력한 하교 기준은 선택한 학교의 하교 자료와 구분합니다. 기존 학교형 ‘다 됐어요’ 조건과 완료 이벤트는 유지합니다.

## 진입과 GA4

- 첫 화면에서 예시를 전환하거나 검색을 열어도 초안을 만들지 않습니다. 첫 방문의 `face=week`와 기존 학교 복원·검색 선택 이벤트 계약을 유지합니다.
- 입학까지 진입은 MY와 기존 직접 주소 및 가이드·홈 링크를 유지합니다. 시간표에서 시작하던 입학까지 이동만 없어지며, 남은 링크의 GA4 페이지뷰, `face=timeline` 및 진입 분류 코드는 바꾸지 않았습니다. 다음 위치 검토에서는 MY를 기본 진입으로 유지하고, 입학 준비에 추가 진입을 넣을 경우 실제 유입 경로를 보고 별도로 결정하는 것을 제안합니다.
- 학교 미선택 답도 명시적 저장입니다. 따라서 첫 일정 입력 전이라도 첫 귀가·하교 응답 때 기존 `timetable_draft_create`가 발생할 수 있습니다. 이후 저장에는 기존 일회 편집·저장 성공 경로를 사용합니다. 학교 미선택 응답에 학교형 질문·완료 이벤트를 추가하지 않았습니다.

## 검증

- 기준 `origin/master`와 PR #13 병합 커밋 `3710058` 확인.
- lint, typecheck, 단위 테스트 211건, build 통과. IPv4 루프백 3000 공개 스모크 187개 PASS. Vite가 제공하지 않는 지역 프리렌더와 홈 예시 JSON은 기존 스모크의 조건에 따라 건너뜁니다.
- 운영 `wherecho.co.kr` 공개 스모크 별도 183개 PASS (후속 첫 진입 전 운영 기준). PR #13 화면 경로를 사용하고, `/timetable`을 일반 쉘로 보던 기존 검증을 실제 배포와 같이 전용 정적 메타 확인으로 보정했습니다. 운영 학교 자료는 공개 읽기, 테스트 일정은 격리된 브라우저 로컬 저장으로 검사했습니다.
- Orca 모바일 Chromium의 360×800·390×844에서 첫 화면, 학교 검색, 학교 없이 시작, 귀가만 응답, 하교 시트와 양쪽 응답 후를 확인했습니다. 17시와 ‘잘 몰라요’ 조합에서 13:40 가정 및 빈 200분이 보이고 새로고침 후 복원됩니다. 운영 이전 화면에는 이 질문 흐름이 없어 첫 화면과 학교 없이 시작까지만 캡처했습니다.
- Orca 연결 기기·에뮬레이터가 없고 이 호스트에 `simctl`이 없어 실제 기기 입력·스크린리더는 미검증입니다.
