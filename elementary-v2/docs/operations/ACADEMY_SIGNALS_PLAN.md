# 학교 주변 기관 — 셔틀·1학년 대상 신호 확보 계획

작성 2026-10-31. 상태: **계획 확정(미착수)**. 같은 날 사용자 결정은 8절.

## 0. 요약

배움·돌봄에서 학교를 고르면 그 학교 주변 학원·교습소·체육도장·돌봄센터 목록을 보여 주고,
**셔틀이 있거나 1학년이 다닐 수 있는 곳을 위로 올린다.** 다른 서비스(런즈 등)의 데이터는
수집하지 않는다(1절). 신호는 근거가 강한 순서가 아니라 **확보하기 쉬운 순서**로 쌓는다.

| 단계 | 신호 | 출처 | 범위 | 시기 |
| --- | --- | --- | --- | --- |
| 1 | 돌봄센터, 체육도장 종목, 체육교습업(줄넘기·축구 등), 학원 교습과정의 '초등' 표기, 학원·교습소 통학차량 등록 | 공개자료(NEIS, 지자체 인허가, 국민체육진흥공단 전국체육시설 정보, 학교안전지원시스템 통학버스 등록현황) | 전국 | 11월 |
| 2 | 셔틀·1학년 반(확인됨) | 운영자 입력(`admin_verified`), 학원 공개 게시물만 | 개편 파일럿 학교 | 12월~ |
| 3 | 셔틀·1학년 반·운행 학교(확인됨) | 학원 자기등록 → 승인(`provider_submitted`) | 파일럿부터 확대 | 1~3월 |
| 4 | "셔틀 있어요" 확인 수 | 그 학원을 시간표에 넣은 부모 | 등록 학원 | **보류**(추후 반영) |

셔틀은 공개자료로 **'통학차량을 등록했다'까지만** 안다. 학교안전지원시스템의 통학버스 등록현황(전국, 공개 엑셀)으로
학원·교습소 7,670곳의 등록이 기존 명단과 연결됐다(2절, 2026-10-28 대조). 이 자료에는 **어느 학교를 도는지와 지금도
운행하는지가 없다.** 그래서 1단계는 '통학차량 등록' 배지까지만 붙이고, '이 학교 셔틀'은 2단계부터 들어간다.

## 1. 하지 않는 것

- **런즈 등 다른 서비스의 학원 정보를 수집하거나 옮겨 적지 않는다.** 저작권법의 데이터베이스제작자
  권리와 부정경쟁방지법의 데이터 부정사용 조항에 걸릴 수 있고, 같은 학부모를 두고 경쟁하는 서비스다.
  프로젝트의 "크롤링한 글은 게시하지 않는다" 원칙과도 맞지 않는다. 런즈는 강남3구·분당 중심이라
  전국을 다루는 어디초에서는 대부분 지역이 비어 있게 된다.
- 허용되는 것: 사람이 화면을 보고 **부모가 어떤 항목을 중요하게 보는지**(셔틀, 픽업, 체험 수업,
  대상 학년) 참고하는 것. 런즈의 데이터를 쓰려면 제휴(API·데이터 계약)를 따로 맺어야 한다.
- 정렬 때문에 신호가 없는 기관을 숨기지 않는다. 위로 올리기만 하고 나머지는 거리순으로 아래에 둔다.

통학차량 등록 대조(2026-10-28, `docs/research/SHUTTLE_GRADE_MATCH_AUDIT_20261028.md`):

- 원본 15,842행 중 학원 9,498·교습소 133행(시험 행 제외). 기존 명단과 이름·주소로 연결된 비율은 학원 79.8%, 교습소 80.5%이고,
  고유 기관은 학원·교습소 합쳐 **7,670곳**이다. 기존 학원 91,360곳 기준으로는 8.3%다.
- 이름만 맞는 689행과 후보가 여럿인 1행은 연결하지 않았다. 연결되지 않은 기관을 '셔틀 없음'으로 보지 않는다.
- 체육도장·수영장은 원본에 분류가 없어 이 자료로 판정할 수 없다. 거점형늘봄센터 8곳은 기존 돌봄 명단에 없다.
- 운영자명·차량번호는 읽지 않으며, 기관별 상세 연결은 git 제외 `etl/runtime/shuttle/`에만 둔다.

## 3. 1단계 실측 — NEIS 교습과정의 학년 표기 (2026-10-07 스냅샷)

`etl/runtime/academy/acainsti_scope_20261007.json`, 직업기술 분야를 뺀 134,604곳.
학원이 직접 쓴 교습과정 목록(`LE_CRSE_LIST_NM`)과 교습비 항목 이름(`PSNBY_THCC_CNTNT`)을 읽는다.
`LE_CRSE_NM`은 NEIS 분류명(97종)이라 읽지 않는다. 규칙 `etl/academy_levels.py`, 검수 기록
`docs/research/academy-levels/README.md`(2026-10-31, 1차 검수 반영 후 수치).

| 분류 | 기관 수 | 비율 |
| --- | ---: | ---: |
| 초등 표기 (1·2학년·저학년 표기 603곳 포함) | 16,119 | 12.0% |
| └ 초등만 | 3,285 | 2.4% |
| └ 초등과 중·고가 함께 | 12,834 | 9.5% |
| 중·고·성인만 | 5,871 | 4.4% |
| 유아만 | 72 | 0.1% |
| 학년 표기 없음 (피아노·미술·외국어·보습 등) | 81,750 | 60.7% |
| 과정·교습비 칸이 모두 비어 있음 | 30,792 | 22.9% |

이 결과에서 다음을 알 수 있다.

- 공개자료만으로 **'초등 과정 등록'이라고 말할 수 있는 곳은 12%**다. 초안에서는 약 20%라고 적었지만,
  `실용외국어(유아/초·중·고)` 같은 NEIS 분류명이 섞여 부풀려진 값이었다. '1학년'까지 좁힐 수 있는 곳은
  603곳(0.4%)뿐이라 따로 배지를 붙이지 않는다. 화면 문구도 "1학년 대상"이 아니라 "초등 과정 등록"으로 쓴다.
- **'중·고·성인만'(4.4%)은 맨 아래로 내린다.** 분류명으로 들어간 '입시'는 빼고 센 값이다.
- 나머지 83.6%는 학년을 알 수 없다. 이 중 예능 분야와 체육도장은 4단계, 그 밖은 5단계에 둔다(5절).
- 사람 검수는 아직 남았다. 볼 것은 검수 기록의 마지막 절에 적었다.

## 4. 단계별 작업

### 1단계 — 공개자료 신호 (11월, 전국)

과목 분류(`etl/academy_subjects.py`)와 같은 방식으로 한다. 공개 `institutions` JSONB에 칸을 하나
더하는 것이라 **마이그레이션이 없다.**

1. `etl/academy_levels.py`(신규): 교습과정 세 칸 → `levels` 태그(`elem`, `secondary`, `preschool`).
   테스트 `etl/tests/test_academy_levels.py`에 오탐 사례('초급', '초견', 기관명 속 '초')를 고정한다.
2. `build_academy_marker_snapshot.py`가 기관마다 `levels`를 싣는다. `merge_sports_dojo_markers.parse_array`가
   새 칸을 버리지 않는지 확인한다. 10-22에 같은 함수가 `subjects`를 버렸던 결함이 있었다.
3. `etl/backfill_academy_levels.py`: dry-run → 사용자 승인 → `--apply`. 바뀐 행만 쓴다.
   이후 월간 `run_academy_refresh.py`가 자동으로 채운다.
4. **DB 용량**: 무료 한도 500 MB에 491.97 MB를 쓰고 있다(10-23 실측). 태그를 짧은 코드로 담으면
   기관당 약 15바이트, 전체 약 2 MB로 추정한다. 적용 전에 `sql/34_reclaim_database_space.sql`이
   적용됐는지 먼저 확인한다.
5. 화면 S1(7절): 배움·돌봄의 학교 화면에 '주변 기관' 목록을 둔다. 지금은 이 화면에 글 목록만 있다.
   기존 RPC `nearby_academy_addresses_for_school` + `nearby_care_centers`로 만든다. 공개 계약은 바뀌지 않는다.
6. 통학차량 등록: `audit_shuttle_registration.py`의 연결 결과로 기관마다 `shuttle_registered`(참일 때만 싣는다)를
   붙인다. `levels`와 같은 경로(마커 빌더 → 월간 학원 갱신)로 낸다. 등록현황 엑셀은 월간 갱신 때 함께 다시 받고,
   원본은 private Storage에 둔다. 이름만 맞는 행은 사람 검수 전에는 싣지 않는다.
7. 체육교습업: `etl/collect_sports_instruction_snapshot.py`(수집) → `etl/geocode_sports_instruction.py`(주소를 학원
   지오코딩 캐시에 추가) → `merge_sports_dojo_markers.py --sports-instruction`(마커). 월간 `run_academy_refresh.py`에
   연결했다. 기관 키는 `sports:{faci_cd}`, 유형은 `체육교습업`, 과목은 `sports`다.
   - API 좌표는 쓰지 않는다. 정상운영 중 19%가 0이거나 비어 있고 다른 시도를 가리키는 값도 있다. 전화번호도 싣지 않는다.
   - 같은 주소에 이름까지 같으면 한 곳으로 센다. 이름이 다르면 둘 다 둔다(지점과 법인명을 원천에서 구분할 수 없다).
   - 수집이 실패해도 학원 갱신은 막지 않는다. 다만 한 달에 15%를 넘게 줄면 체육도장과 같이 멈춘다.
   - 화면 문구는 '학원·교습소·체육시설'로, 출처에는 전국체육시설 정보를 더했다. 문구는 `release` 배포로, 데이터는 월간 실행으로 들어간다.

검증: 단위 테스트, 표본 검수표(분류별 200곳), dry-run 차이 보고, 서울대현초·분당 한 곳의 목록 화면 확인.

### 2단계 — 운영자 입력 (12월~, 개편 파일럿 학교)

`FRONTYARD_PLAN.md` 5절의 '12월~ [모집해요] 운영자 입력'과 같은 일이다. 셔틀·학년 칸은 SQL 33에
이미 있다(`provider_programs.shuttle`, `grade_min`·`grade_max`, `provider_program_school_targets`).

- 범위: **개편 파일럿 학교로 한정한다.** 범위를 정하는 기준은 다른 세션의 매니페스트
  (`etl/build_pivot_pilot_manifest.py`, 규칙은 `docs/operations/PIVOT_PILOT_ETL.md`)이며, 이 문서에 학교 목록을
  따로 두지 않는다. 2026-10-20 기준으로 학군지 10곳과 위례의 298개교이고, 운영 파일럿인 분당·판교·위례가 먼저다.
  순서는 그 세션의 진행 순서를 따른다.
- 대상: 파일럿 학교 주변 800m 안의 학원 가운데 1단계에서 통학차량 등록·'초등 과정 등록'으로 잡혔거나 예능·체육도장인 곳.
  통학차량 등록 학원은 운행 학교만 확인하면 되므로 먼저 본다.
  학교당 거리순 상위 20곳에서 시작한다.
- 근거: **학원이 스스로 공개한 게시물만 쓴다**(8절 결정 3). 학원 홈페이지, 학원 명의의 블로그·SNS 공지,
  학원이 게시한 전단·모집 안내가 여기에 해당한다. 전화 확인은 하지 않는다.
  학부모 커뮤니티 글, 다른 서비스 화면, 지도 앱 리뷰도 근거로 쓰지 않는다.
- 근거마다 출처 URL과 게시일·확인일을 남긴다(`last_confirmed_at` = 확인일). 게시일이 직전 학기보다 오래된
  게시물은 셔틀 근거로 쓰지 않는다.
- 셔틀은 '운행함'으로만 끝내지 않고 **운행 학교**를 `school_targets`에 넣는다. 부모에게 필요한 건
  "우리 학교에서 타는가"이기 때문이다. 게시물에 운행 학교가 없으면 셔틀은 비워 둔다(`NULL`).
- 공개 게시물이 없는 학원은 입력하지 않는다. 1단계 신호로만 정렬되고, 3단계 자기등록을 기다린다.
- 확인 결과는 검수표(`docs/research/academy-signals/`)에 먼저 쌓는다. 운영 적재는 사용자 확인 뒤에 한다.

### 3단계 — 학원 자기등록 (1~3월)

- 흐름: 학원이 [모집해요]에서 등록을 요청하면 운영자가 승인한다. 본인 확인 방식(등록번호 대조,
  대표번호 회신 전화)은 `FRONTYARD_PLAN.md` 7절의 열린 질문으로 남아 있다.
- 입력 칸: 셔틀 여부·운행 학교, 학년 범위, 하교 직후 시간대(`provider_program_sessions`), 교습비 문구.
- 신선도: `last_confirmed_at`이 120일을 넘으면 '확인 필요'로 표시하고, 정렬 가중치를 1단계 수준으로 내린다.
  학기가 바뀔 때(2월·8월) 재확인을 요청한다.
- 학원법상 교습비 표시 의무 등 광고 표시사항은 오픈 전에 확인한다.

### 4단계 — 부모 확인 (보류, 추후 반영)

2026-10-31 사용자 결정으로 보류한다. 아래는 다시 꺼낼 때 출발점으로 남겨 둔 초안이다.

- 그 학원을 시간표에 '다니는 중'으로 넣은 부모에게 "셔틀 타나요? 예/아니요/모름" 한 번만 묻는다
  (`parent_schedule_entries.provider_key` 기준).
- 서로 다른 부모 3명 이상이 '예'라고 답하면 '부모 N명 확인'을 붙인다. 학원 입력을 덮어쓰지 않고 따로 보인다.
- 아이 이름, 타는 위치, 귀가 동선은 묻지 않는다(앞마당 6절 원칙).
- 새 테이블이 필요하다(SQL 번호 미정). 설계는 3단계가 자리 잡은 뒤에 한다.

## 5. 정렬 규칙

2026-10-31 사용자 확정. 신호마다 단계를 두고, 같은 단계 안에서는 거리순으로 놓는다. 신호를 합산하지 않는다.
점수를 합치면 왜 위에 있는지 부모에게 설명할 수 없기 때문이다.

| 순서 | 조건 | 배지 |
| --- | --- | --- |
| 1 | 셔틀이 이 학교를 운행함(확인됨, 2~3단계) | 셔틀 · 학원 등록 10/31 |
| 2 | 1학년 반 있음(확인됨) 또는 돌봄센터 | 1학년 반 / 돌봄센터 |
| 3 | 공개자료에 초등 과정 등록(1단계) | 초등 과정 등록 |
| 4 | 통학차량 등록(1단계, 운행 학교 미확인) | 통학차량 등록 |
| 5 | 학년 표기는 없지만 예능·체육도장·체육교습업 | (배지 없음) |
| 6 | 그 밖 | (배지 없음) |
| 7 | 중·고 과정만 등록 | 중·고 과정 |

2026-11-01 사용자 확정:
- 1순위는 운행 학교가 확인돼야 하므로 2~3단계부터 채워진다. 그전까지는 비어 있고, 1단계 화면의 맨 위는 2·3순위다.
- 통학차량 등록은 1학년 반·초등 과정 등록보다 **아래**(4순위)에 둔다. 어느 학교를 도는지 모르는 차량보다
  1학년이 다닐 수 있는지가 먼저다. 10-31 확정 때는 공개 셔틀 자료가 없다고 보고 이 단계가 빠져 있었다.
- 여러 신호가 있는 기관은 높은 쪽 순위에 두고 배지는 모두 보인다(초등 과정 등록 + 통학차량 등록이면 3순위, 배지 둘).

배지에는 출처를 붙인다. 확인된 신호는 날짜를 보이고, 공개자료에서 추정한 신호는 "공개자료"라고 적는다.
과목 칩(`subjects`) 필터와 함께 쓸 수 있게 한다.
