# 신축 아파트 단지 유입 계획

작성 2026-10-07. 상태: **계획 — 착수 전 결정 4건 필요(2절)**.

## 0. 요약

단지 목록은 `archive/GAS/GAS/임시/apt_mst_info_202410.csv`(2024-10 기준) 하나로 정해진다.
`build_apartment_master_v1.py`는 이 파일의 단지마다 K-apt 행을 찾아 속성을 채울 뿐이다.
그래서 K-apt에 새로 올라온 단지는 매월 갱신을 몇 번 돌려도 앱에 들어오지 않는다.

2026-10-02 K-apt(22,551행) 중 우리 마스터가 쓰지 않는 단지 코드는 2,521개다. 사용승인일로 나누면:

| 사용승인 | 단지 | 비고 |
|---|---|---|
| 2026 | 184 | |
| 2025 | 399 | 2025년 이후 합계 583곳, 약 40만 세대 |
| 2024 | 326 | 기준 파일(2024-10) 이후분이 섞여 있다 |
| 2023 이전 | 1,612 | 대부분 기존 단지의 매칭 실패나 범위 밖으로 본다 |

이사를 앞둔 부모가 가장 많이 찾을 신축 입주 단지가 빠져 있다. 이 계획은 K-apt에만 있는 신축 단지를
**보충 기준 파일**로 만들어 매월 단지 목록에 더한다.

## 1. 구조

```
이 PC (매월 1일 21:00, Elementary Local Monthly ETL)        GitHub Actions (매월 2일 03:15)
 3 신축 보충  ← 새 단계                                        apartment 그룹
   K-apt 최신본 → 기준 파일에 없는 신축 후보                     base + 보충 파일로 마스터 빌드
   → 기존 단지와 중복 제거 → VWorld 좌표                          → 보충 행의 점 배정은 파일에 이미 있음
   → 학구도 폴리곤 점 배정                                       → 업로드, serving 재생성
   → 보충 파일을 Storage에                                     academy 그룹(새 단지 근접도 포함)
                                                               공개 키 발급 (결정 D3)
```

이 PC가 맡는 이유는 학원과 같다. 좌표는 VWorld로만 얻을 수 있고, VWorld는 해외 IP를 막는다.

### 보충 기준 파일 `apartment_base_supplement.csv`

- `apt_mst_info_202410.csv`와 같은 열을 쓴다. 그래야 빌더가 두 파일을 그대로 이어 읽는다.
- `apt_cd`는 `KAPT` + K-apt 단지코드다(예: `KAPTA12345678`). K-apt 코드는 바뀌지 않으므로 공개 키의 원자(atom)로
  쓸 수 있다(ADR-007). 기준 파일의 `apt_cd`와 형식이 달라 서로 겹칠 수 없다.
- 좌표, 세대수, 동수, 사용승인년도, 법정동코드는 K-apt 행과 VWorld 결과에서 채운다.
- 점 배정 결과(`apartment_point_assignments` 형식)도 같은 단계에서 만들어 함께 둔다. 그러면 러너에
  shapefile과 shapely가 필요 없다.

## 2. 착수 전 결정

| # | 결정 | 권고 | 이유 |
|---|---|---|---|
| D1 | **신축 후보 기준** | 사용승인일이 **2024-07 이후**이고, 반경 150m 안에 세대수 ±10%인 기준 단지가 **없는** K-apt 단지 | 2023년 이전 1,612곳은 대부분 기존 단지의 매칭 실패다. 넣으면 같은 단지가 둘로 보인다. 기준 파일과 겹칠 수 있는 3개월을 두고, 거리·세대수로 한 번 더 거른다 |
| D2 | **경계 근처 신축의 배정** | 점 배정이 `high`인 단지만 바로 공개. 경계 50m 안 등 `needs_building_check`는 공개하되 "배정 확인 필요" 표시 | 신축은 동 좌표가 아직 없어 건물 단위로 정밀 배정을 못 한다. 숨기는 것보다 표시하고 보여주는 편이 부모에게 낫다 |
| D3 | **공개 키 발급 위치** | 키 목록의 원본을 이 PC 파일에서 **DB(`apartment_public_key*` 테이블)로 옮기고**, Actions가 serving 재생성 직전에 발급 | 지금 원본은 이 PC의 `apartment_public_keys.json`뿐이다. 러너가 발급하지 못하고, 파일을 잃으면 위험하다. DB에는 이미 사본이 있다 |
| D4 | **첫 반영 범위** | 리허설 보고서(지역별 추가 단지 수, 표본 20곳 지도 확인)를 본 뒤 전국 한 번에 | 지역마다 나눠 넣으면 학원처럼 지역 경계에서 일관성이 깨진다 |

## 4. 위험

| 위험 | 대응 |
|---|---|
| 같은 단지가 둘로 보임 | D1 필터. 리허설 보고서에서 기존 단지와 150~300m 사이 후보를 따로 보여 사람이 본다 |
| 보충 단지가 다음 달 기준 매칭에 잡혀 이중 반영 | 보충 행은 기준 파일 매칭 대상에서 빼고 K-apt 코드로만 잇는다 |
| 신축이 K-apt에서 이름을 바꿈 | `apt_cd`가 K-apt 코드라 이름이 바뀌어도 같은 단지다. 이름 이력은 기존 이력 테이블로 간다 |
| 학구도 새 판에서 신축지 경계가 바뀜 | 학구도 반기 갱신 절차(별도 작업)에서 보충 점 배정도 함께 다시 만든다 |
| 이 PC가 꺼져 있음 | 보충 파일이 갱신되지 않을 뿐, 지난달 보충분은 Storage에 남아 계속 쓰인다 |
