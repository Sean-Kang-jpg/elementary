# 시간 미확인 돌봄의 시간표 기본 가정

2026-10-20. 사용자가 선택한 돌봄을 계획 단계에서 배치하는 화면 변경이다. 운영 DB의 실제 시간·운영 상태는 변경하지 않았다. 운영 배포는 수행하지 않았다.

- 아침 시간 미확인: 선택한 요일에 08:00–09:00 기본 가정. 명시적인 미운영 상태는 선택 대상에서 제외한다.
- 오후 종료 미확인: 정규수업 하교부터 17:00 종료 기본 가정. 기존 저장된 시각 미확인 돌봄에도 적용한다. 확정 자료·직접 수정·방학 일정은 덮어쓰지 않는다.
- 하교 시각까지 미확인: 시작을 만들지 않는다. 하루 보기에는 ‘하교 후–17:00 · 기본 가정 · 시작 확인 필요’, 주간에는 17시 종료 표지를 배치한다. 길이와 공백 분은 계산하지 않는다.
- 방과후·맞춤형은 돌봄과 함께 선택한다. 기존 복귀 구간 계산을 사용하여 ‘강좌 종료 → 오후돌봄 15:00–17:00’처럼 안내한다.
- 저녁돌봄은 오후돌봄 종료 이후다. 종료 자료가 없으면 17:00 시작이 채워진 입력 화면에서 종료를 직접 입력한다. 입력 전 종료시각을 생성하지 않는다. 입력 후 선택한 요일의 계획에 포함하며, 다른 요일 추가 시 기존 입력 시각을 유지한다.
- 돌봄 자료 자체가 없는 학교에도 기본 계획 선택지를 제공한다. 조회 실패는 자료 없음과 구분하여 재시도를 안내한다.
- `ScheduleEntry.timeAssumption`은 계획용 표식이다. 기본 시간은 estimated이며 실제 운영 확인·참여 확정을 뜻하지 않는다. 원본 공개 테이블과 저장된 기존 원문 값을 갱신하지 않는다.

## 검증

- `npm run test:unit`: 95개 통과. 기존 저장 돌봄의 순서, 원본 불변, 실제·수정 시각 보존, 방과후 복귀, 하교 미확인 예외를 포함한다.
- `npm run typecheck`, `npm run lint`, `npm run build`: 통과. 전체 빌드는 공개 데이터 조회가 허용된 환경에서 사이트맵 생성까지 확인했다.
- `scripts/care-planning-defaults-smoke.mjs`: 로컬 전용 fixture로 ‘시간 미기재’와 ‘자료 자체 없음’을 각각 재현. 실제 브라우저에서 선택 → 기본 가정 표시 → 방과후 복귀 → 저녁 종료 입력 → 주간 배치 → 저장 후 재조회 → 다른 요일 추가 → 하교 시각 미확인 종료 표지까지 통과했다. 390px 가로 넘침·페이지 오류 없음.
- 화면 확인: `etl/runtime/care-planning-defaults-20261020.png` (Git 제외 경로).
- 운영 `npm run browser:smoke:public -- https://wherecho.co.kr` 통과. 이는 현행 운영 서비스의 회귀 점검이며 신규 코드의 운영 배포 검증은 아니다.

React 검토: 훅 순서·기존 비동기 취소 처리·목록 키·버튼 접근성·저장 성공 후 처리 확인. 새로운 외부 호출이나 DB 쓰기를 추가하지 않았다.
