# E05/E06 LLM 추출 시험: 하이쿠와 소네트 (2026-10-09)

지역을 더 넓히기 전에 시정·돌봄 추출을 자동화할 수 있는지 시험했다. API는 쓰지 않았다. Claude Code 하위 에이전트가 학교별 발췌 파일만 읽고 JSON을 썼다. 정답 세트(파일럿 + 성남·강남3구 확대, 208곳)는 추출기에 보이지 않게 했다.

## 구성

| 파일 | 역할 |
| --- | --- |
| `etl/llm_extraction_inputs.py` | 학교별 발췌 `[CLOCK]`·`[CARE]` 작성(`etl/runtime/llm_extraction/inputs/`) |
| `etl/llm_extraction_spec.md` | 추출 지시서와 JSON 형식 |
| `etl/llm_extraction_check.py` | 정답과 무관한 검증(근거 구절이 원문에 있는지, 그 구절에 시각이 들어 있는지, 시각 순서)으로 자동 승인을 정하고 정답과 대조해 채점 |
| [care_review_corrections_20261009.json](care_review_corrections_20261009.json) | 세 판독(정답·하이쿠·소네트)이 엇갈린 학교를 원문과 대조한 수정 목록(**사용자 확인 전**) |

26곳씩 8배치, 같은 입력과 지시서로 두 모델을 돌렸다.

## 결과(수정된 정답 기준)

| | 하이쿠 | 소네트 |
| --- | --- | --- |
| 시정 정확도(109곳) | 68.8% | **98.2%** |
| 시정 자동 승인율 | 34.9% | **86.2%** |
| 시정 자동 승인분 정확도 | 94.7% | **98.9%** (94곳 중 93) |
| 돌봄 정확도(208곳) | 81.2% | 98.6% |
| 돌봄 자동 승인분 정확도 | 90.8% | 98.6% |

**목표(승인분 정확도 98% 이상, 승인율 70% 이상)는 소네트만 넘었다.** 하이쿠는 1학년이 아닌 열의 4교시를 고르거나, 5교시 시작 시각을 종료 시각으로 쓰거나, 아침돌봄·방과후 프로그램 시간을 돌봄 시간으로 쓰는 오류가 반복됐다.

남은 소네트 오류는 다음과 같다.
- 언북: 1·2학년 열이 앞에 붙은 표를 시정표로 인식하지 못했다.
- 노화북: 학년별 급식 시작(12:35) 대신 표의 급식 시작(12:30)을 썼다. 자동 승인된 유일한 오답이다.
- 돌봄 3곳: 안락·부곡은 연장 시각의 해석이 갈렸고, 가거도는 일과표의 돌봄교실 칸을 시간으로 썼다.

**주의.** 돌봄 수정 59곳은 모두 원문과 대조했다. 다만 두 모델이 같은 값을 낸 곳에서 출발했기 때문에, 돌봄 수치는 소네트에 유리하게 기울었을 수 있다. 새 지역에서는 정답 세트를 따로 만들어 표본으로 다시 재야 한다.

## 정답 세트의 오류

1차 검수가 놓친 것이 모델보다 많았다.
- **돌봄 59곳**
  - 53곳은 "학교 확인"이었지만 원문에 시간이 있었다.
  - 6곳은 시간이 달랐다.
  - 원인은 발췌 검색에 있었다. 1차 검수의 구절 검색이 구절 수를 제한했고, 전담사·봉사자 행 근처를 건너뛰었다.
  - 이 중 6곳(가락·송전·영풍·원촌·송례·잠현)은 2026-10-08 사용자 확인 때 "연장만 적힘 → 학교 확인"으로 결정한 학교다. 원문에는 기본 종료(방과후~17:00 등)가 있었다.
- **시정 1곳**: 대치초를 "행사 일정표뿐"으로 제외했지만, 같은 문서에 전 학년 공통 정규 시정이 있었다.
