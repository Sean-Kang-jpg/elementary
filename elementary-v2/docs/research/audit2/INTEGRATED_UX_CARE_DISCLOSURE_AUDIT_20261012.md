# 통합 UX·돌봄 공시 Audit — 2026-10-12

## 확인 범위와 경계

이번 변경은 학교알리미 `apiType=59`, 검수된 학교알리미 15-라 운영계획, 다함께돌봄센터 공개 목록 및 현재 프런트 렌더링만 다룬다. 다른 작업자가 수행 중인 전국 아파트 배치와 방과후 과목 분류·1학년 신청 가능 과목 DB 갱신은 수정하지 않았다. 이 작업 사본에는 개발 시안이 있으나 운영 조회 함수는 여전히 `null`을 반환한다. 사용자가 제공한 “개발 완료·DB 갱신 중·미배포” 맥락은 보존하되, 타 팀 코드와 원격 DB 갱신 진행률·최신 배포 상태는 이번에 독립 확인하지 않았다.

## 정규화 규칙

1. 원천 숫자 `0`은 “공시 0”, 빈 문자열·비수치·누락은 `NULL`(미공시 또는 미확인)로 저장한다.
2. `statistics_year`는 공시 발행연도이며 학년도라고 단정하지 않는다. 15-라 문서에서 확인된 `source_year`, `source`, `reviewed_on`은 별도 계약으로 유지한다.
3. 오후돌봄 기본 종료, 별도 저녁/연장 종료, apiType=59 저녁돌봄 교실 수를 독립 필드로 취급한다.
4. 돌봄교실 수와 참여인원은 공시 사실값이다. `참여인원 ÷ 1·2학년 학생 수`와 `참여인원 ÷ 교실 수`는 참고 계산값이며 여석, 경쟁률, 입소 가능성을 뜻하지 않는다.
5. 1학년 방과후 연계형 돌봄 대상은 운영계획/가정통신문의 명시 근거가 있을 때만 가능으로 표시한다. 자료 부재는 `미확인`이며 `불가`로 바꾸지 않는다.
6. 지역 돌봄시설의 모집·예약기간과 신청 링크는 공식 페이지와 확인일이 있는 경우에만 표시한다. 정원은 시설 정원일 뿐 현재 여석이 아니다.

## 확정 IA

- 지도는 하나를 유지한다.
- 상위 필터는 `학교`, `방과후·돌봄`, `배정·통학`, `배움·활동` 네 영역으로 정리한다.
- 학교·아파트·돌봄센터·활동시설 선택 결과는 공통 바텀시트 컨테이너를 사용하되 유형별 탭과 데이터 계약을 분리한다.
- 기존 `/school/*`, `/apt/*`, `/area/*` URL과 검색/학구 진입 경로는 보존한다.

## 통합 백로그

### P0 — 이번 변경

- 지역/하위행정구역 마커를 초등학교 총수 하나로 단순화.
- 공시 0과 미공시·미확인 렌더링 분리.
- 오후 기본 종료와 별도 저녁돌봄 공시의 개념 분리.
- 이용률/교실당 인원을 여석 신호로 해석하던 문구 제거.
- ETL 숫자 정규화 회귀 테스트 추가.

### P1 — 이번 UX 구현 / 미배포

- 홈의 지역별 배정 비교 배너와 입학 준비의 데이터 리포트 배너를 React 화면·정적 페이지 양쪽에서 제거했다. `/area`는 홈 하단의 작은 학교 목록 링크로 보존하고 `/news` URL도 유지한다.
- 네 상위 영역과 학교 상세 탭을 같은 상태로 연결했다. 학교에는 설립 유형·학년·학생 수, 방과후·돌봄에는 기존 별도 저녁돌봄 교실 공시 조건, 배정·통학에는 세대수·주차, 배움·활동에는 기존 시설 분야 분류를 배치했다.
- 학교 상세는 학교 / 방과후·돌봄 / 배정·통학 / 배움·활동, 아파트 상세는 배정·통학 / 지역 돌봄 / 배움·활동 탭을 사용한다. 학교 영역 선택 시 아파트 대신 배정 학교 상세로 이동한다.
- 돌봄센터는 운영·이용 안내 / 출처·확인, 활동시설은 시설·분야 / 출처·확인 탭을 공통 `BottomSheet`로 연다. 지도 SDK 팝업 대신 유형별 상세 상태를 사용하고 뒤로 가기로 시설 시트를 닫는다. 센터 목록에도 상세 버튼을 제공한다.
- 지역 돌봄 조회는 아파트 탭에서도 **선택된 학교 기준 직선거리 1km**이다. 거리 선택은 추가하지 않았다. 활동시설의 기존 600m/800m 생활권 분류는 돌봄 거리와 별개로 유지한다.
- 배움·활동은 현재 배정 아파트 생활권 기반 시설 집계이다. 초등 대상 강좌·모집 여부는 검증된 값이 없어 단정하지 않으며, 지원 입학 학교/공시 부재 때문에 집계하지 못하는 경우를 시설 없음과 구분한다.
- 정원은 여석이 아니며, 원천 수정일과 별도 운영 확인일을 구분한다. 확인일이 없으면 미확인이다. 공식 모집기간/신청 링크의 출처·확인일 필드는 아직 없으며, 이번에 임의 생성하지 않았다.

## P1 QA 결과

- `lint`, `typecheck`, 전체 `build`(Vite + 정적 페이지 + SEO 생성) 통과. 학생·아파트 sitemap과 `/area` 페이지 목록 생성 유지.
- 프런트 단위 테스트 32개, 돌봄 정규화·운영계획·학구 매칭 관련 Python 테스트 19개 통과. SQL, 학구 QA 게이트, ETL 업로드/배치 로직은 수정하지 않았다.
- `scripts/p1-ux-smoke.mjs` 통과: 실제 공개 데이터로 배너 삭제, 학교/아파트 딥링크·홈 검색, 종속 조건, 탭 동기화, 학교 기준 1km, 메뉴 포커스·Escape, 360/390/430/1280px 가로 넘침을 확인했다.
- 시설 상세는 `scripts/fixtures/map-place.html`의 개발용 표본으로 0/NULL 정원, 출처, 확인일 미확인, 단일 시트, 닫기·뒤로 가기를 확인했다. **이 표본은 운영 DB 정합성 또는 실제 마커 클릭 검증이 아니다.** 운영 빌드의 진입점에서 참조하지 않는다.
- 대현초 표본의 센터 목록은 화면상 0곳이었다. 기존 서비스가 미배포 RPC 오류도 빈 배열로 반환할 수 있으므로, 이를 실제 주변 센터 부재의 증거로 사용하지 않는다.
- 전체 `public-smoke`는 `127.0.0.1:3012`와 `localhost:4173`에서 지도 단계 실패. SDK 콘솔은 `500 / Internal Server Error`를 반환했으나 기존 앱은 이를 주소 인증 오류로 표시했다. **지도 지역 집계·마커 클릭·전체 성능 게이트는 미통과이며 배포 전에 재실행해야 한다.** 해당 게이트를 삭제하거나 완화하지 않았다.
- 기존 청크 크기·Browserslist 데이터 경고는 남아 있다. 공식 센터 현황 링크는 기존 수집기의 출처 주소를 재사용했으나 이번 외부 조회는 실패해 최신 링크 유효성을 검증 완료로 처리하지 않았다.

## 수동 검수 및 배포 전 게이트

- apiType=59 원문 행과 15-라 운영계획을 같은 학교·같은 연도로 묶어 `오후 종료 19:00 + 저녁돌봄 0실`, `NULL`, `0`, 양수 사례를 각각 표본 검수한다.
- 전국 학구 fixture와 기존 학교/아파트 딥링크 회귀 테스트를 유지한다.
- 방과후 과목 DB 갱신 완료 후 분류 정확도 표본, 1학년 가능 여부의 근거 문서, production 조회 계약을 별도 QA한다.
- 배포 전 lint, typecheck, build, unit, public smoke를 모두 통과해야 한다. 이 문서는 운영 DB 변경 또는 배포 완료를 의미하지 않는다.
