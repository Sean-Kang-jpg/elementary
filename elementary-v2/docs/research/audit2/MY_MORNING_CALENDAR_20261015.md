# MY 아침돌봄부터 보는 시간표

## 화면 결정

사용자가 아침돌봄을 선택하면 같은 월~금 열 안에서 **아침 일정 → 정규수업 축약 → 오후 일정** 순서로 표시한다. 별도의 텍스트 요약과 오후 표로 분리하지 않는다. 아침돌봄 선택이 없거나 마지막 아침 일정이 취소·미선정되면 기존 12:00~19:00 보기를 유지한다.

- 아침 시간축은 선택한 일정의 실제 시각을 바깥쪽 정각으로 감싸 정한다. 07:30~08:40이면 07:00~09:00을 표시한다. 5개 요일이 하나의 공통 시간축을 사용하며 원천 시각·요일·신청 상태는 변경하지 않는다.
- 정규수업은 64px 행으로 축약하고 종류·프로그램명과 예상 하교 시각을 표시한다. 왼쪽에 ‘수업 축약’ 표시와 끊어진 구간의 배경을 둔다. 축약 전후의 시간 간격이 동일하지 않음을 본문에 명시한다. 등교시각·정규수업 시작을 09:00으로 확정하거나 새로 저장하지 않는다.
- 오후는 기존 12:00~19:00, 72px/시간 그리드를 유지한다. 정규수업 카드의 중복은 없애고 정오 이후 예상 하교까지는 ‘정규수업 중’ 옅은 배경으로 표시해 빈 시간으로 오해하지 않도록 한다. 오후 5분 생성·이동 좌표 계산은 바꾸지 않는다.
- 시각 미확인 아침돌봄은 맨 앞 미확인 행에서 안내하고 임의의 시간 위치에 넣지 않는다. 아침돌봄은 선택한 요일에만 표시한다. 다른 요일의 ‘선택한 아침 일정 없음’은 운영 여부 판단이 아니다.
- 모바일에서 세 구간이 함께 가로 스크롤되며 왼쪽 시간축은 고정된다. 파스텔·단순 분야 SVG 아이콘·두 줄 카드·장식 테두리 없음 원칙을 유지한다.
- 아침 원천 카드를 누르면 전체 시각·참여 상태·출처를 확인할 수 있다. 학교 자료는 직접 이동·수정할 수 없다. 오전 개인 일정은 상세 양식으로 시간을 수정할 수 있고, 직접 드래그는 기존 오후 그리드에서만 지원한다.

## 데이터 작업과의 경계

현재 개발 중인 아침돌봄 선택 모듈이 저장한 기존 `ScheduleEntry`를 그대로 읽는다. 이름·출처의 아침 표시와 오전 돌봄 시각을 식별한다. DB·ETL·데이터 적재·자동 신청·요일 추정은 추가하지 않았다. 다른 아침돌봄 정보·선택 모듈은 유지하고 MY 시간표에 전달할 때 오전 일정을 제외하던 필터만 제거했다.

## 검증

- `npm run lint`, `npm run typecheck`, `npm run build`(사이트맵 포함) 통과. 단위 검사 82개 통과.
- `morningCalendar.test.ts`: 아침 미선택·취소·미선정·방학, 공통 오전 범위, 앞선 개인 일정, 미확인 시각, 정규수업 시작 가정 배제, 원천값 불변, 오전 겹침 열 배치를 확인했다.
- `my-morning-calendar-smoke.mjs`: 별도 브라우저에서 월/수만 아침 카드 표시, 시각·높이(07:30 시작과 70분 길이), 64px 수업 축약, 공통 오후 축 정렬, 예상 하교, 출처 상세·수정 보호, 오후 5분 이동, 모바일 내부 가로 스크롤·시간축 고정, 미확인 시각의 상단 안내, 마지막 아침 선택 취소 후 기존 보기 복구, 런타임 오류 없음을 확인했다.
- `node scripts/morning-care-render-smoke.mjs` 통과. 기존 아침돌봄 선택/정보 컴포넌트 호환을 유지한다. `morning-care-smoke.mjs`의 별도 요약 검사 조건은 새 요일별 통합 표시 조건으로 갱신했다.
- 전체 공개 검사는 `npm run browser:smoke:public -- http://localhost:3012`로 실행했으나 Vite preview가 `/map`에 앱 전용 셸 대신 홈 HTML을 반환해 실패했다. 운영 rewrite와 다른 로컬 preview의 주소 처리 한계이며 전체 게이트 통과로 보고하지 않는다. 운영 배포는 하지 않았다.

`my-morning-calendar-20261015.png`와 `my-morning-calendar-20261015-mobile.png`는 격리된 검사용 일정이며 실제 학교 운영·참여 확정을 뜻하지 않는다.
