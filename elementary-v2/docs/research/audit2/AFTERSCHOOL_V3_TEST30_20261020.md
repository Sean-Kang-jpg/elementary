## 검증 방법

다른 소네트 에이전트가 같은 원문을 읽고, 운영 데이터와 v3 결과를 X·Y로 섞은 맹검 묶음에서 행마다 맞고 틀림을 판정하고 빠진 반을 찾았다(`etl/llm_verify_spec_v3.md`, `etl/v3_verify_packets.py`, `etl/v3_verify_score.py`). 비교 대상은 화면에 나가는 행이다(v3는 기간 학기, 1학년판정 false 제외).

## v3에 남은 문제

1. **표가 깨진 맞춤형 요일표**: HWP인데도 일부 표는 텍스트 상자·탭으로 짜여 있어 격자가 없다(B000001915, B000001846). PDF만 있는 학교(B000001839)도 마찬가지. v3는 요일·시각을 비워 두는 쪽으로 처리했고, 검증은 이를 오류로 셌다. 틀린 값이 아니라 빈 값이다.
2. **특수학급 강좌**: 특수교육대상 학생 전용 반이 들어갔다(B000001849 4행 등). 지시서에 제외 규칙이 없었다.
3. **기수별 같은 반 중복**: 1기·3기 표에 같은 반이 다시 나와 중복 행이 생겼다(B000001888). 기수마다 따로 둘지 합칠지 정해야 한다.
4. **여러 반을 합친 운영 시간대**: B000001843처럼 "13:00~17:20, 4개 반"만 적힌 표를 한 반의 시간으로 썼다. 운영 데이터도 같고, **검증 에이전트도 잡지 못했다.** 실제 정확도는 위 숫자보다 조금 낮다.
5. **판정 기준이 애매한 경우**: '돌봄반 안의 맞춤형교실'(B000001854, B000001868)을 맞춤형으로 볼지, 본안·수정안이 표시 없이 두 번 있는 경우(B000001841).
