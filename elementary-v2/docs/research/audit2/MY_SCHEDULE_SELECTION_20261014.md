# MY 시간표: 과목 선택과 가로 요일 보기

## 화면 결정

모바일에서 하루 일정의 이름·시각을 읽고 요일을 비교하기 위해 월~금 열을 한 줄로 배치한다. 화면에 다음 요일 일부를 남기고 가로 스크롤과 월~금 바로가기 버튼을 함께 제공한다. 키보드로도 이동할 수 있다. 넓은 화면에서는 다섯 요일을 동시에 보여 주며 MY 본문을 최대 1000px로 넓힌다.

후속 사용자 요청에 따라 캘린더 방식으로 바꿨다. 왼쪽에 12:00~19:00 공통 시간축을 고정하고 각 요일에 30분 보조선과 1시간 기준선을 표시한다. 확인된 일정은 시작·종료에 맞춰 배치하고, 겹치는 일정은 별도 열로 나눈다. 정규수업은 예상 하교까지, 돌봄은 해당 요일의 하교 후 시작으로 표시한다. 미확인 시각은 시간축에 배치하지 않고 각 요일 아래에 안내한다. 표시 범위를 넘는 일정은 원래 시각을 유지하면서 그림만 잘라 보여 주며, 완전히 범위 밖인 일정도 아래에 안내한다. 짧거나 겹친 블록은 클릭·키보드로 상세 이름·시각·참여 상태·출처를 확인할 수 있다.

시간표 아래의 메뉴는 요청한 문구인 ‘방과후/맞춤형/돌봄 선택하기’, ‘추가 일정 입력하기’로 제공한다. 선택 메뉴를 펼치면 실제 반별 선택 목록과 ‘선택한 일정 관리’가 나오며 기존 참여 상태 변경·삭제 기능을 유지한다.

돌봄은 방과후·맞춤형과 독립적으로 동시 선택할 수 있다. 돌봄 중 수업은 일반 수업끼리의 시간 충돌과 구별해 중립적인 연계 계획 안내로 표시한다. 시간이 확인된 선택 수업의 마지막 종료가 돌봄 종료보다 이르면 남은 돌봄 구간을 함께 안내한다. 시각 미확인 수업이 있는 날에는 복귀 시각을 추정하지 않는다. 실제 이동·복귀 조건은 기존대로 학교 확인 대상으로 남긴다. 원래 돌봄 운영 시간이나 참여 상태를 자동 변경하지 않는다.

시간표 블록과 프로그램 선택 버튼은 텍스트 두 줄만 표시한다. 첫째 줄은 ‘종류 · 프로그램명’, 둘째 줄은 시각이다. 같은 종류가 이름에 반복되는 경우 표시에서만 정리한다(예: ‘정규수업 · 4교시’, ‘돌봄 · 오후’). 요일·대상 학년은 선택 버튼 밖에 표시하고 참여 상태·출처·예상 여부는 상세·접근성 이름에 유지한다. 긴 이름과 시각은 한 줄 말줄임이며 눌러서 전체 내용을 확인할 수 있다.

## 선택 흐름

- 초안 만들기는 예상 하교만 가져온다. 돌봄 기본·연장은 각각 명시적으로 선택한다.
- 시간표 아래 선택 메뉴를 펼치면 전체·돌봄·맞춤형·방과후 필터, 과목 검색, 반별 선택 버튼을 제공한다.
- 반을 고르면 원천 요일·시각·출처를 저장하고 `planned`(계획에 포함)로 시간표에 표시한다. 다시 누르면 해당 일정만 제거한다. 실제 신청·참여 확정과는 별개다.
- 학년 적합성은 강좌 요약이 아닌 반별 값으로 표시한다. 모르는 시각은 채우지 않는다. 요일이 없으면 이름·시간을 채운 직접 입력 양식을 열고 요일은 선택하지 않은 상태로 둔다.
- 요일을 보완한 일정도 원래 반의 ID를 유지해 재선택 중복을 막는다. 학교 전환 시 다른 학교의 입력 초안을 적용하지 않는다.
- 기존 시간표는 보존한다. 기존 후보를 선택하면 계획 포함으로 바꾸되 저장된 시각·요일을 유지한다. 다른 탭의 최신 저장 내용에서 해당 일정만 갱신한다.
- 시간 겹침과 돌봄 중 수업을 구분한다. 자료 조회 실패·재시도·자료 미확인·검색 결과 없음도 구분한다. 저장 실패 시 선택된 것처럼 표시하지 않는다.

## 데이터 연결 상태

2026-10-14 연결 프로젝트 `elementary_v2.0`의 공개 조회 및 읽기 전용 DB 확인에서 `school_afterschool_summary`, `school_afterschool_programs`는 아직 없고 서울대현초의 `school_care_hours`는 조회된다. 사용자 확인: 30개 학교 검수가 끝나지 않아 강좌 자료는 로컬에만 있고 운영 배포 전이다.

강좌는 기존 공개 데이터 조회 함수를 그대로 사용하므로 SQL 30과 검수된 자료의 운영 적재 후 선택 목록에 연결된다. 이번 UX 작업은 DB·ETL·자료 적재를 변경하지 않는다. MY에 개발용 대체 자료를 저장하지 않는 기존 원칙도 유지한다.

## 검증

- lint, typecheck, build(사이트맵 포함) 통과.
- 단위 검사 61개 통과. 선택한 반의 요일·시간·근거를 유지하며 계획에 배치하고 참여 확정 없이 충돌을 계산하는 검사와, 시간축 경계·겹침 열·정확히 이어지는 일정의 열 재사용·수업 이후 돌봄 연계 구간 검사를 추가했다.
- 기존 `my-ux-smoke.mjs` 통과: 초안 비교·내 시간표 전환·새로고침·관심 후보 삭제와 시간표 보존·저장 실패·실제 서울 학교 조회. 기존 세로 행 크기 검사는 공통 12~19 시간 그리드 높이와 내부 가로 스크롤 검사로 변경했다.
- `my-schedule-smoke.mjs` 통과: 시간축 12:00~19:00, 14~15시 블록의 정확한 위치·높이, 겹침 열, 미확인 시간의 그리드 제외, 스크롤 중 시간축 고정, 블록 상세, 변경된 메뉴 문구·순서를 검증했다. 로컬 전용 격리 응답으로 반별 선택·자동 입력·해제·중복 방지·누락 시각·누락 요일 보완·검색·겹침·돌봄 중 수업·조회 실패/재시도·저장 실패·360/390/430/768/1280px·키보드/요일 이동도 검증했다. 실데이터 검사는 분리해 강좌 테이블 미적재는 SKIP로 명시했고 서울 돌봄의 조회·선택·출처 저장은 통과했다. 종료 미확인 돌봄 시각은 추측하지 않는다.
- 공개 전체 회귀 검사를 개발 서버에서 실행했다. 공유 이미지·사이트맵·주소 origin 일치와 앱 진입 검사는 통과했다. 첫 검사에서는 네이버 지도 SDK가 HTTP 500을 반환했고 지역 마커 단계가 완료되지 않았다. 재검사에서는 지역 마커가 표시됐으나 줌 아웃 후 시도 마커 전환 조건이 시간 내 충족되지 않았다. 전체 게이트는 미통과로 기록하며 이번 시간표 범위에서 지도 코드를 변경하지 않는다. 배포 경로 분리와 서버 prerender도 개발 서버에서는 확인하지 않았다.
- 돌봄 동시 선택·두 줄 버튼 개편 후 전용 브라우저 검사와 기존 MY 검사는 모두 통과했다. 돌봄 해제 시 수업 두 개 유지, 수업 해제 시 돌봄 유지, 복귀 시각 안내·시각 미확인 시 복귀 추정 제외, 두 줄 구조·이름 중복 제거를 추가 검증했다. `my-care-plan-20261014.png`와 `my-care-plan-20261014-choices.png`는 격리된 검증용 일정 캡처다. 이번 공개 전체 검사는 `district data loaded and measured` 대기에서 시간 초과했으며 전체 게이트 통과로 보고하지 않는다.

실행 예:

```text
node scripts/my-schedule-smoke.mjs http://localhost:3012 <화면 캡처 경로.png>
node scripts/my-ux-smoke.mjs http://localhost:3012
npm run browser:smoke:public -- http://localhost:3013
```

운영 배포는 이번 요청 범위에 포함하지 않았다.
