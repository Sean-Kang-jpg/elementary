## 학교별 판단

### 초림

PDF p3/L14는 월~금 활동명을 학년별로 공시한다. 초1은 월 칼림바·화 공예·수 체육놀이·목 창의놀이 메이커스·금 보드게임이다. 초2는 월 공예·화 칼림바·수 보드게임·목 체육놀이·금 창의놀이 메이커스다. 아침돌봄의 아침독서는 월~금 공통이지만 시각은 없다.

`주중12~16:30`은 전체 운영 창이며 각 맞춤형 반의 시각이 아니다. 이를 5개 활동의 시작·종료로 사용하지 않았다. 필수인 초1 맞춤형 5요일의 시각이 없어 해당 항목은 검수 보류다. PDF p4/L16의 토요 오케스트라3~6학년09:00~12:00은 1학년 대상이 아니어도 원시 행에 보존했다.

수익자 시각은 원문 그대로 기록했다. 미술B14:50~16:10을 다른B반의14:30~15:50으로 맞추거나, 클라리넷A/B의 시간 중첩을 임의 수정하지 않았다. 아침·토요·고학년을 삭제하지 않았고, 방학의 전체 운영창을 학기별 활동에 복제하지 않았다. 돌봄 내부 계획은 별도 작성이므로 미운영이라고 판정하지 않는다.

추가 조사에서는 [공식 초1·2 맞춤형 게시판](https://www.goesn.kr/chorim-e/na/ntt/selectNttList.do?mi=26609&bbsId=20659), [방과후 게시판](https://www.goesn.kr/chorim-e/na/ntt/selectNttList.do?mi=16957&bbsId=13836)을 확인 대상으로 식별했다. 2학기 신청 안내는 검색 결과에 있으나 첨부 원문 확보·대조가 완료된 것으로 표시하지 않았다. 게시판 목록 추가 조회는 자동 승인 검토의 사용량 한도로 실행되지 않았다.

### 안말

PDF p4/L17~19는 학년·교실별 40분 수업 2차시를 보여 준다. 초1은 수·금13:00~13:40 및13:50~14:30, 월·화·목13:50~14:30 및14:40~15:20이다. 통합반도 같은 운영창이나 **신청 인원이 한 학급을 초과할 경우 개설**한다. 통합반의 10개 원시 행에 `confirmed_operating=false`인 별도 조건을 연결했다. 실제 개설로 단정하거나 확정 선택 목록으로 표시하면 안 된다.

수업 종료와 하교지도도 구분한다. 수·금은14:30수업 종료 뒤14:30~14:40하교, 월·화·목은15:20수업 종료 뒤15:20~15:30하교로 표에 나뉜다. 하교 구간은 활동 행으로 생성하지 않았다.

PDF p5의 선택형 교육은 요일별 칸에 대상 학년을 적어 운영일을 표시한다. 평탄화된 텍스트에서는 요일 대응이 없어 원본 표로 직접 대조했다. 컴기초는 수요일, OA마스터는 화요일, 컴퓨터 자격증A는 목요일·B는 수요일, AI코딩은 금요일이다. 반·과정을 구분해 보존했다.

현재 학기 검수는 미완료다. 문서 L12와L14의 학기·방학 날짜가 일치하지 않고 시작 시각·과목 변경 가능성도 명시한다. 2026년2학기 모집 안내와 통합반 개설 여부를 추가 확인해야 한다. 선택형 돌봄·방학은 별도 계획이 필요하다.

### 성남장안

학교 전체 대상은 L20의 `1~6학년 희망자`다. L64~109의 세부 시간표에는 반별 학년 열이 없어 모든 수익자 행에 학년출처`school`을 기록했다. A반이 저학년, B반이 고학년이라는 추정은 하지 않았다. 1학년에게 적합한 수준인지까지 검증됐다는 뜻은 아니다.

단일 연간 강좌표 외에1~4기 운영 일정이 있지만 기수별 강좌표는 없다. 같은46행을 기수별로4배 복제하지 않았다. 주간표와 세부표에 일부 교실 차이가 있어 위치 확정도 미완료다. 본문에 초1·2맞춤형 활동·시각표가 없으므로 별도 맞춤형 자료가 필요하다. 현재 감사는 `grade1_custom_inventory_complete=false`를 유지한다.

## 검증 자료와 실행

- 원시 행: `p1_stage2_manual_20261023/batch_stage2_<school_id>.json`.
- 원문 대조·신청 단위·보류 사유: `p1_stage2_manual_review_20261023.json`.
- 부분 감사 결과: `p1_stage2_manual_audit_20261023.json`.
- 앞선 준비 상태인 `p1_stage2_inputs_20261023.json`은 이번 실행 전에 고정한 입력 스냅샷이다. 현재 추출 진행 상태는 위 부분 감사 결과와 공통 진행표를 기준으로 확인한다.

```powershell
python -m etl.pivot_p1_stage2_audit --manifest docs/research/pivot/p1_stage2_inputs_20261023.json --review docs/research/pivot/p1_stage2_manual_review_20261023.json --out docs/research/pivot/p1_stage2_manual_audit_20261023.json
python -m unittest etl.tests.test_pivot_p1_stage2_audit etl.tests.test_pivot_p1_stage2_packets etl.tests.test_load_school_afterschool etl.tests.test_afterschool_rules etl.tests.test_pivot_p1_v3_inputs etl.tests.test_pivot_p1_review_gate etl.tests.test_pivot_p1_participation etl.tests.test_publish_seoul_gap37_append etl.tests.test_portable_inputs
```

실제 실행 결과: **66개 테스트 통과**, 입력·원본·출력 해시·14칸 형식·근거 행 번호·모든 원시 행의 검수 결정·신청단위 묶음 일치 확인. 초림 필수시각 공백5행, 안말 미확인 조건부10행, 성남장안 맞춤형 목록 불완전이 보존된다. 전체161행은 동일 에이전트가 원문을 읽고 기록한 결과이며, 독립 정확도나 맹검 결과가 아니다.

기존 적재기 함수를 메모리에서만 호출해3개교를 읽는 호환성을 확인했다. 이 함수는 신청 단위·조건부 개설을 운영 화면까지 연결하지 않으므로, 만들어지는 SQL 행123개는 진단용 개수다. 실제 확정 강좌 수나 적재 완료 수가 아니다. DB 연결, `--apply`, 공유 운영 출력 교체는 하지 않았다.

## 작업 경계와 다음 순서

원본 입력과 운영 ETL·DB·P2·화면은 수정하지 않았다. 전용 브랜치에 원시 자료·보류 조건·새로운 로컬 감사 실행기와 테스트만 추가했다. master의 프런트야드·학원·공통 입력 사전검사 변경은 가져오지 않았다.

다음은 남은36개교의 전체 원문 추출이다. 초림 시각과 성남장안 맞춤형 대체 원문, 안말 현재 학기 및 조건부 개설은 보완 목록에 남겨 병행한다. 전39개교를 대조하고 별도5개교 독립 표본검증을 받은 뒤 운영 loader·화면 연결을 검수한다. 현 단계 운영 적재 승인은 없다.
