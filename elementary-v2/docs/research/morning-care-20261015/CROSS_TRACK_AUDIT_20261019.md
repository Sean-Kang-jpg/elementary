- 아침 표본 40개교 중 12개교가 맞춤형 작업자 배정에도 있었다. 같은 학교·원문을 사용하더라도
  아침 운영/신청/정원/동행과 맞춤형 강좌명/요일은 다른 추출 항목이다. 원문 수집은 재사용하고 필드를 분담한다.

- 위 검사는 시간·요일 표의 대응, 학기/방학, 유료/무료 분류, 학년 해석의 의미 검증을 대신하지 않는다.

## 단독·통합·분리의 입력량 비교

서울 606개교의 저장 텍스트 1,114개를 로컬에서 읽었다. 다운로드·LLM 호출·DB 쓰기 없이 계산했다.
아침 후보 문구 ±12줄, 기존 방과후 wide 규칙, 맞춤형 ±12줄을 선택하고 파일별 문자 상한을 적용했다.
공통 원문 줄을 한 번만 보내는 통합 방식과 각각 보내는 분리 방식을 비교했다.
아침 후보 선택 규칙은 진단용이며 운영 데이터용 추출기나 재현율 검증을 마친 규칙이 아니다.

| 방식 | 선택된 본문 문자 수 | UTF-8 바이트 |
|---|---:|---:|
| 아침만 | 1,984,906 | 4,251,840 |
| 방과후·맞춤형만 통합 | 8,133,812 | 16,190,378 |
| 아침·방과후·맞춤형 통합 | 9,015,059 | 18,079,528 |
| 아침 / 방과후·맞춤형 2개 작업으로 분리 | 10,118,718 | 20,442,218 |
| 아침 / 방과후 / 맞춤형 3개 작업으로 분리 | 11,588,195 | 23,255,791 |

이 선택 규칙에서 통합 본문은 2개 작업 분리보다 문자 수가 약 10.9%, 3개 작업 분리보다 약 22.2% 적었다.
이는 토큰 또는 비용 절감률이 아니다. 프롬프트, 학교·파일·줄 번호, 출력, 에이전트 문맥, 도구 사용,
추론 토큰, 캐시 효과를 제외했으며 세 방식의 정확도도 비교하지 않았다.
아침 후보 문구가 잡힌 452개교를 아침돌봄 운영 학교 수로 쓰면 안 된다.

이미 방과후·맞춤형 추출을 마친 현재 상태에서는 아침 항목만 추가 검토하는 편이 중복 작업을 줄인다.
DB에 저장된 값을 프로그램으로 조회하는 행위 자체에는 LLM 토큰이 들지 않는다.

정확한 입력 토큰 비교는 사용할 모델 ID와 실제 요청 내용을 고정한 뒤 모델별 토큰 계산으로 측정해야 한다.
Claude의 token-counting은 입력을 세며 캐시 효과는 반영하지 않는다. 출력·도구 등 실제 사용량은 요청의 usage와
함께 기록해야 한다. [Anthropic 공식 설명](https://platform.claude.com/docs/en/build-with-claude/token-counting).

## 5.6 서브에이전트 적용 판단

GPT-5.6 Sol은 복잡한 전문 작업용 모델이며 이 환경의 서브에이전트 선택 목록에도 있다.
[OpenAI 공식 모델 안내](https://developers.openai.com/api/docs/models/gpt-5.6-sol).
학교 문서 추출에서의 충분한 정확도나 현재 모델 대비 토큰 절감률은 아직 실험으로 확인하지 않았다.

권장 운영은 정해진 JSON 변환·명시된 시간/학년 추출·누락 검사에는 5.6 Sol을 시범 적용하고,
병합 셀·방학/학기 혼재·정원/현원·조건부 운영·출처 충돌은 별도 검토하는 방식이다.
우선 기존 검수 표본의 동일 원문으로 정확도와 실제 usage를 비교한 후 범위를 넓힌다.
이번에는 추가 서브에이전트를 실행하거나 다른 세션 모델을 변경하지 않았다.
